# Задача для Codex: даты в прошлом + слишком низкий бюджет (воронка «Туры»)

> План/диагностика: Claude. Реализация: Codex. Ревью: Claude.
> Контекст: реальный ТГ-диалог 30.06.2026. Клиент — Египет, 2 взр + 2 детей (6, 10),
> 5–12 августа, бюджет 2000$, всё включено. Бот ответил «Поиск временно недоступен» и спихнул
> менеджеру. Это уже ПОСЛЕ деплоя фиксов childage/region/meal.

## Диагноз (подтверждён на API TourVisor)

### Проблема A — даты в прошлом → исключение (УЖЕ ПОЧИНЕНО, нужно ревью+деплой)
LLM передал `dates='05.08.2025-12.08.2025'` (год прошлый: клиент сказал «август» без года,
модель подставила 2025). TourVisor на прошлую дату отвечает `{"error":"dateto - bad format."}` →
поднимается `TourVisorError` → ветка `except` в `app/agent/runner.py` (`_tours_exec_tool`) даёт
«Поиск туров сейчас временно недоступен».
Проверка API: `datefrom=05.08.2025` → `dateto - bad format`; `…2026` → `requestid` (OK).

**Уже сделано (в рабочей копии, не задеплоено):** в `app/integrations/tourvisor/client.py`,
функция `_parse_dates` — если распарсенная дата в прошлом, переносим на ближайший будущий год
(цикл `while d1 < today: d1,d2 = +1 год`). Локальный тест: `05.08.2025-12.08.2025 → 05.08.2026-12.08.2026`.
**Codex:** проверить эту правку, оставить, покрыть тестом (`tests/`), задеплоить.

### Проблема B — слишком низкий бюджет → пустая выдача → тупик (НУЖНО СДЕЛАТЬ)
После фикса дат поиск отрабатывает без ошибки, но возвращает **0 отелей**, потому что
`budget='2000 USD'` → `priceto=2000`, а реальные цены Египет 2+2 AI на эти даты — **3153–3485 USD**
(проверено: без ценового потолка тот же запрос даёт 5 отелей). Сейчас бот на 0 результатов скажет
«Подходящих туров не нашлось» и уйдёт к менеджеру — клиент не понимает, что просто бюджет мал.

**Что нужно:** когда поиск С ценовым потолком вернул 0, сделать повторный поиск БЕЗ `priceto`
(или с расширенным потолком), и:
- если есть варианты выше бюджета — показать 2–3 самых дешёвых и ЧЕСТНО сказать, что под бюджет
  не выходит, минимальная реальная цена — от X (валюта из выдачи), предложить поднять бюджет
  или другой курорт/даты;
- только если и без потолка пусто — тогда уже передавать менеджеру.

Реализация — на усмотрение Codex, варианты:
- в `TourVisorClient.search` (или `_tours_exec_tool`): если `priceto` задан и результат пуст →
  второй проход без `priceto`, вернуть с пометкой «over_budget» (мин. цена), чтобы агент честно
  подал это клиенту;
- учесть, что у бота тон Frunze (Сезим): тепло, коротко, без выдуманных цен.

### Кодовая спека (ревью Claude — держись её, если нет причин отступить)

> Разбор кода сделан: точка врезки — `TourVisorClient.search` в `app/integrations/tourvisor/client.py`.
> Источник истины «был ли потолок» — сам собранный `query` (`query.get("priceto")`), повторно
> парсить бюджет НЕ нужно. `_build_query` кладёт `priceto`/`pricefrom`/`pricetype` только когда
> бюджет задан (стр. ~197–202). `_format_hotels(hotels, limit=5)` уже умеет строки выдачи.

**1. Врезка в `search()`** — между `hotels = await self._poll(client, request_id)` и
`return _format_hotels(hotels)` (внутри `try`, до `except TourVisorError`):

```python
hotels = await self._poll(client, request_id)
# Бюджет мал → пустая выдача. Один повторный проход без ценового потолка и честно про мин. цену.
if not hotels and query.get("priceto"):
    budget = query["priceto"]
    for key in ("priceto", "pricefrom", "pricetype"):
        query.pop(key, None)
    retried = await self._call(client, "search.php", query)
    request_id = str(retried.get("result", {}).get("requestid") or retried.get("requestid", ""))
    if request_id:
        hotels = await self._poll(client, request_id)
        if hotels:
            return _format_over_budget(hotels, budget)
return _format_hotels(hotels)
```

Только ОДИН повторный проход (не цикл). Если и без потолка пусто → `_format_hotels([])` вернёт `[]`,
а раннер скажет «Подходящих туров не нашлось» (дальше агент сам решит про менеджера) — это ок,
значит реально ничего нет.

**2. Хелперы** — рядом с `_format_hotels` (модульный уровень):

```python
def _hotel_price(h: dict) -> int:
    """Числовая цена лучшего тура отеля — для сортировки «самые дешёвые». Нечитаемое → +∞."""
    best = (_as_list((h.get("tours", {}) or {}).get("tour")) or [{}])[0]
    try:
        return int(str(best.get("price", "")).replace(" ", ""))
    except (TypeError, ValueError):
        return 10**9


def _format_over_budget(hotels: list[dict], budget: int) -> list[str]:
    """Бюджет мал: 2–3 самых дешёвых + приписка-инструкция агенту про честную мин. цену."""
    cheapest = sorted(hotels, key=_hotel_price)
    lines = _format_hotels(cheapest, limit=3)
    best = (_as_list((cheapest[0].get("tours", {}) or {}).get("tour")) or [{}])[0]
    mn, cur = best.get("price", ""), best.get("currency", "")
    notice = (
        f"⚠️ Под бюджет {budget} вариантов нет. Минимальная реальная цена — от {mn} {cur}. "
        "Покажи клиенту эти 2–3 самых дешёвых, честно скажи, что в бюджет пока не укладывается, "
        "и предложи поднять бюджет или сменить даты/курорт. Цены не выдумывай."
    )
    return [notice] + lines
```

Приписка `notice` — это инструкция АГЕНТУ (как уже сделано в `handoff_to_manager`: текст уходит в
LLM как tool-result, а не клиенту дословно). Агент переформулирует тёпло в тоне Сезим. Сортировка
обязательна — TourVisor НЕ гарантирует порядок по цене, а мы заявляем «минимальная».

**3. Промпт (по желанию, страховка)** — в `app/agent/prompts/tours.py` одно правило: если результат
поиска начинается с «⚠️ Под бюджет…» — не выдумывай, назови честно мин. цену и предложи поднять
бюджет/сменить даты.

### Тесты (новый файл `tests/test_tourvisor_client.py`)
Чистые функции (без сети):
- `_parse_dates`: `05.08.2025-12.08.2025` → `05.08.2026-12.08.2026` (диапазон сохранён); одиночная
  прошлая дата → окно +14 дней в будущем; будущая дата не трогается.
- `_hotel_price`: берёт цену лучшего тура; «3 153» → 3153; мусор → 10**9.
- `_format_over_budget`: сортирует по возрастанию, первый строкой идёт `⚠️`-notice с мин. ценой и
  валютой из выдачи, дальше ≤3 строк.

Интеграция `search()` (мокнуть `self._call` и `self._poll`): 1-й `_poll` → `[]`, 2-й → отели →
`search` возвращает notice+строки; проверить, что во 2-м вызове `search.php` НЕТ `priceto`
(потолок снят). И путь «оба пусто» → `[]`.
