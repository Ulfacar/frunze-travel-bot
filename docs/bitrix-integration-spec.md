# ТЗ для разработчика Bitrix24 — интеграция бота Frunze Travel / GetVisa

**Портал:** `getvisakg.bitrix24.kz` (облако).
**Что за бот:** внешний сервис (Python), ведёт WhatsApp-диалоги (через Wappi), квалифицирует
клиентов и должен **создавать и двигать сделки в вашем Bitrix24** (3 направления: Визы, Туры, Билеты).

Есть два пути. **Быстрее всего — Путь А** (дать нам входящий вебхук): тогда мы сами вытащим все
ID воронок/стадий/полей и всё настроим. Если доступ дать нельзя — заполните **Путь Б**.

---

## Путь А (рекомендуем) — входящий вебхук

1. Создайте **«Входящий вебхук»**: Разработчикам → Другое → Входящий вебхук.
2. Права (scope): **`crm`**, **`user`**.
   *(Если решим заводить WhatsApp как Открытую линию Bitrix — добавить `imopenlines`, `imbot`, `im`.)*
3. Пришлите URL вида: `https://getvisakg.bitrix24.kz/rest/<user_id>/<token>/`

Этого достаточно — остальное (CATEGORY_ID, STAGE_ID, коды полей) мы получим сами по REST.

**Какие методы будем вызывать** (чтобы вы понимали объём прав):
- `crm.category.list`, `crm.category.stage.list` / `crm.status.list` — прочитать воронки и стадии;
- `crm.deal.add`, `crm.deal.update`, `crm.deal.list`, `crm.deal.fields` — создавать/двигать сделки;
- `crm.contact.add`, `crm.duplicate.findbycomm` — находить клиента по телефону, не плодить дубли;
- `crm.deal.userfield.list` (и при необходимости `.add`) — пользовательские поля;
- `user.get` — ответственные менеджеры.

## Путь Б — если доступ дать нельзя, пришлите значения

1. **Режим CRM:** «Лиды + Сделки» или «Простой CRM» (только Сделки)?
2. **Воронки (CATEGORY_ID):** для Визы, Туры, Билеты (или подтвердите: Билеты = воронка Туров).
3. **Стадии (STAGE_ID)** каждой воронки — по таблице маппинга ниже.
4. **Коды полей (UF_CRM_…)** сделки — по таблице полей ниже (или: «писать в комментарий/таймлайн»).
5. **Ответственные:** ID менеджеров + правило назначения (очередь по кругу / конкретный на направление).
6. **Контроль дублей:** искать клиента по номеру телефона? Как настроено у вас.
7. **Канал WhatsApp:** оставляем Wappi (внешний, как сейчас) или заводим Открытую линию Bitrix?
   Если линия — нужны `CONFIG_ID` линии + `BOT_ID` чат-бота (imbot) на каждый бренд
   (`frunze_tours`, `getvisa`) и кто регистрирует imbot.

### Таблица 1. Маппинг стадий (наш ключ → смысл → ваш STAGE_ID)

| Наш внутренний ключ          | Колонка / смысл          | STAGE_ID (заполнить, напр. `C2:NEW`) |
|------------------------------|--------------------------|--------------------------------------|
| `new`                        | Новый                    |                                      |
| `qualification`              | Квалификация             |                                      |
| `visa_scoring` / `selection` | Подбор / Оценка          |                                      |
| `office_consultation`        | В офис (консультация)    |                                      |
| `manager_handoff`            | У менеджера              |                                      |
| `won`                        | Успех / Оплатил          |                                      |
| `lost`                       | Слив / Отказ             |                                      |
| `followup`                   | Повторное касание        |                                      |

### Таблица 2. Поля сделки (что пишет бот)

| Данные                | Пример                | UF-код (заполнить) |
|-----------------------|-----------------------|--------------------|
| Направление / страна  | США / Турция          |                    |
| Даты поездки          | 10–17 авг             |                    |
| Состав                | 2 взр + 1 реб         |                    |
| Бюджет                | 1500$                 |                    |
| Тип визы              | туристическая         |                    |
| Прошлые отказы        | отказ США 2023        |                    |
| Температура лида      | hot / warm / new      |                    |
| Summary от ИИ         | кратко по клиенту     |                    |
| Следующий шаг         | пригласить в офис     |                    |
| Источник              | WhatsApp / getvisa    |                    |

> Имя и телефон клиента — в **контакте** сделки (не в полях выше).

## Технические детали нашей стороны (для согласования)

- Бэкенд читает конфиг: `bitrix24_webhook_url`, `bitrix_category_by_funnel` (`{tours, visa, tickets}`),
  `bitrix_stage_map` (`{внутренняя_стадия → STAGE_ID}`). Один портал, вебхук портал-уровня.
- **Когда пишем:** сделка создаётся при первом сообщении клиента; далее по ходу диалога бот обновляет
  стадию и поля (несколько вызовов на один диалог).
- **Идемпотентность:** одна сделка на диалог (ключ `bot_id:phone`), дубли сверяем по телефону.
- Объём трафика небольшой (десятки диалогов в день на старте).
