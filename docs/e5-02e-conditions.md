# E5-02E — явные условия шести черновых режимов

Добавлена локальная проверка профиля по условиям `KG.SP.HK_MACAO`, `KG.SP.UN_LP`,
`KG.SP.CHN_IND_LONGTERM_VISA`, `KG.SP.CHN_TOUR_GROUP`, `KG.VF.GCC` и
`KG.VR.SIMPLIFIED_GCC_RESIDENT_TS`. Результат каждой проверки: **met / not_met / unknown**
и недостающие факты. Это совпадение заявленного профиля с условиями черновика, не право въезда.

`app/knowledge/condition_schema.py` задаёт строгие схемы каталога и фактов;
`app/knowledge/conditions.py` выполняет проверку. Источник каталога — непосредственно
прочитанные physical pages 22/23 и pinned capture Б.5 (88/89) исходного PDF.
Структурированные условия живут отдельно в `knowledge/kg_entry/conditions_v1_1/catalog.json`,
связаны с **source_hash + bundle_hash**. Старые 208 единиц/импортированные snapshots остаются
неизменными, у этих шести единиц по-прежнему NULL value. Новая интерпретация условий не
переписывает исторический bundle и не выдаётся за его утверждение.

## Правила проверки

| Профиль источника | Явные условия |
|---|---|
| HK/Macao | Постоянное проживание в HKG/MAC; гражданство не подменяет проживание |
| UN LP | Тип документа `un_lp`; гражданство для этого предиката не требуется |
| CHN/IND + long-term visa | Страна въездного паспорта CHN/IND; одна виза нужного региона с отдельно проверенным признаком «строго больше трёх лет» |
| CHN tour group | Паспорт CHN; организованная группа 5–25 включительно, все участники граждане CHN, ходатайство органа туризма |
| GCC citizens | Страна въездного паспорта в списке гражданств Б.5; проживание в GCC само по себе условие не выполняет |
| GCC/Brunei residents TS | Одно из 12 гражданств Б.5, TS, отдельно проверенный лимит до одного месяца, один ВНЖ/резидент-карта одной из семи стран из 2.4 |

Для виз и резидентских документов все признаки должны совпасть **в одной записи**.
Нельзя взять страну из одного документа и тип/длительность из другого.
`items` + `complete` описывают перечень документов: найдено совпадение → met;
нет совпадения при неполном перечне → unknown; полный перечень только несовпадений → not_met.
Неизвестные поля внутри документа тоже сохраняют unknown, если они могут изменить результат.
В конъюнкции известное несовпадение даёт not_met; подробные checks показывают остальные пробелы.

`over_three_years_verified`: true только после проверки условия «>3 лет», false если
проверено, что оно не выполнено; null/отсутствие — неизвестно. Источник не уточняет способ
оценки срока визы; модуль не выбирает между общим и оставшимся сроком и не считает годы.
Аналогично `stay_within_one_month_verified`: отдельное заключение проверяющего, **не 30 дней**.
Эти поля не следует автоматически заполнять LLM из догадок.

Значения дней/окон/повторного въезда и ограничения виз внутри КР сохранены в `source_outcome`
как сведения источника. Исключение форс-мажора из 2.5 сохранено у HK/Macao и тургрупп.
Рабочее разрешение GCC остаётся unknown. Этот модуль не считает дни/окна, не проверяет
повторный въезд, действительность/подлинность документов, даты действия норм или весь список
стоп-факторов. Для неописанных типов паспортов нужна отдельная проверка применимости.

## Запуск и воспроизведение

```powershell
python -X utf8 scripts/build_kg_entry_conditions.py --check --pdf "..\Kyrgyzstan-visa-knowledge-base-v1.1.pdf"
python -X utf8 scripts/review_kg_conditions.py knowledge/kg_entry/draft-v1.1 --source "..\Kyrgyzstan-visa-knowledge-base-v1.1.pdf" --facts tests/fixtures/kg_entry/synthetic_condition_facts.json
python -m pytest tests/test_kg_conditions.py -q
```

Builder читает зафиксированные capture/aliases, проверяет их хеши, извлекает числа из
Б.5/текста и строит стабильный JSON. `--pdf` повторно сравнивает capture с исходным PDF.
Без `--check` создаёт только отсутствующий файл; изменённый существующий результат не
перезаписывает. Ошибка записи может оставить неполный новый файл — для повторной попытки
после устранения причины используйте новый `--output`. `--check` никогда не пишет.
Builder использует существующий PyMuPDF только при прямой PDF-сверке; новых зависимостей нет.

Review CLI хеширует реальный source, валидирует bundle, проверяет привязку каталога и факты.
Python API `ConditionReview` принимает уже вычисленный source_hash от вызывающей стороны.
Идентичность source/bundle не доказывает юридическую актуальность или авторство каталога.
`catalog_hash` в ответе — SHA256 canonical JSON (порядок списков значим), а не SHA файла.
SHA256 файла каталога: `3e499dd29aa7c0dba1d338d48b7d0ca64c4ca98277509c2506f706d32a9b890c`.

Факты ограничены нужными полями; имена, номера паспортов, контакты и неизвестные поля
отклоняются. Ответ не повторяет входную анкету. CLI read-only, без .env/DB/network/LLM.
Код 0 — проверка выполнена (включая unknown/not_met); код 1 — ошибка входов/источника.

Всегда `publication_approved=false`, `may_quote=false`, `selected_regime=null`.
Дата источника — source_claim. Каталог ещё не подключён к боту, country DB index или
публикации; старый country review index по-прежнему показывает 5 unmapped исходных единиц.
Новый каталог описывает их профильные условия отдельно, не устраняя неизвестные значения.
Независимая сверка/утверждение, DEC-07, прежние CRITICAL gates остаются открытыми.
