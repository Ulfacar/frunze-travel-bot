Автор: Claude (планирует + ревьюит). Исполнитель: Codex (пишет код, свой визуал графиков). Режим Веном.

## Контекст (что УЖЕ есть — НЕ переписывать)
Страница `/admin/analytics` (`app/admin/router.py:316-339`, шаблон `app/admin/templates/analytics.html`,
расчёт `app/integrations/panel/analytics.py`) уже отдаёт: KPI-карточки, панель «Сегодня»,
containment, горизонтальные бары исходов, CSS-график активности за 7 дней (`a.activity` с полем

и админ-блок LLM-бюджета. Данные `by_manager` и `activity` уже считаются в `compute_analytics`.

Задача — НЕ строить дашборд заново, а: **(1) закрыть страницу под полного админа**,
**(2) добавить настоящие графики**, **(3) обогатить разрез по сотрудникам**.

## Часть 1 — доступ только для админа (обязательно, security)

Сейчас `/analytics`, `/system`, `/audit` защищены `require_admin`, который проверяет ТОЛЬКО факт
логина (`app/admin/router.py:167-172`), а не роль. Значит скоуп-менеджер (Сезим/Медина) заходит на
аналитику и видит статистику своих ботов. Владелец хочет, чтобы вся статистика была только у админа.

Полный админ определяется существующей `_manager_bot_scope(manager) is None`
(`app/admin/router.py:183-192`; после [[spec-admin-second-account]] сюда добавится флаг `admin:true`).

### 1a. Новая зависимость в `app/admin/router.py` (рядом с `require_admin`, ~строка 172)
```python
def require_full_admin(request: Request) -> dict:
    """Пускаем только полного админа (видит все воронки). Скоуп-менеджер → 403."""
    m = require_admin(request)                 # сперва проверка логина (401)
    if _manager_bot_scope(m) is not None:
        raise HTTPException(status_code=403, detail="admin only")
    return m
```

### 1b. Применить гейт
Заменить `Depends(require_admin)` → `Depends(require_full_admin)` в:
- `analytics` (`router.py:318`) — обязательно.
- `system` (`router.py:343`) и `audit` (эндпоинт аудита) — тоже (статус системы и аудит-лог
  логически админские). Если где-то у audit-роута другой guard — привести к `require_full_admin`.

### 1c. Прятать ссылки у не-админа (UX, не полагаться только на URL)
- В обработчик `boards` (`router.py`, рендер `boards.html`) добавить в контекст
  `is_admin = _manager_bot_scope(manager) is None`.
- В `boards.html:256-259` обернуть ссылки 📊 Аналитика / ⚙️ система / 📋 аудит в `{% if is_admin %}…{% endif %}`.
- Аналогично скрыть перекрёстные ссылки «Аудит →» в `faq.html:57`, `system.html:55`, `audit.html:34`
  при желании (не критично — эндпоинты уже под гейтом).

## Часть 2 — обогатить статистику по сотрудникам (`compute_analytics`)

В `app/integrations/panel/analytics.py`, функция `compute_analytics`, блок `by_manager`
(строки 126, 141-144). Сейчас на менеджера есть: `handled` + счётчики исходов (`won/office/lost/…`).
Добавить на каждого менеджера:
- `won_rate` — процент оплат: `round(100 * won / handled)` при `handled>0`, иначе 0.
- `avg_response_min` — среднее время ответа этого менеджера (минуты). Собрать per-manager:
  в цикле по диалогу response-паузы (уже считаются в `response_gaps`, строки 150-158) складывать
  ещё и в бакет менеджера `c.assigned_to`, затем усреднить через `_avg`.
- `share` — доля от всех переданных менеджерам диалогов: `round(100 * handled / sum_handled)`.

Формат сохранить как dict на менеджера (шаблон уже читает `st.get(...)`). Сортировку по `handled`
оставить. Отфильтровать пустой ключ `assigned_to == ""` (сейчас в прод-данных 151 диалог с пустым
`assigned_to` — это «бот сам», не сотрудник; в `by_manager` он не попадает, т.к. блок под
`if c.assigned_to`, но проверить, что пустая строка не протекает).

## Часть 3 — графики (визуал; Codex делает свой дизайн, self-contained)

Требование: **никаких внешних CDN/скриптов** — только инлайн CSS + инлайн SVG (как уже сделано
для `.chart`/`.obar`). Тёмный шрифт Google Fonts в `analytics.html:7` можно оставить (панель —
онлайн-приложение), но графики рисуем без внешних JS-библиотек.

Добавить в `analytics.html` (Codex сам решает вёрстку/палитру, консистентно с текущим стилем):

1. **График по сотрудникам** (главное по запросу) — горизонтальные бары «вёл диалогов» на каждого
   менеджера, ширина ∝ `handled`, рядом бейдж `won_rate%` и `avg_response_min`. Заменить/дополнить
   существующую таблицу «По менеджерам» (`analytics.html:125-138`). Пустой список → текущий муут-текст.

2. **Containment-донат** — SVG-кольцо «бот сам vs передано менеджеру»
   (`a.contained` vs `a.total - a.contained`), в центре — `containment_rate%`.
   Реализация без библиотек: `<svg>` + `<circle>` со `stroke-dasharray`.

3. **Сплит по воронкам** — бар/донат «туры vs визы vs билеты». Тотал на воронку = сумма стадий:
   в шаблоне `{% set ftotal = stages.values()|sum %}`, либо (чище) добавить в `compute_analytics`
   готовый `funnel_totals = {f: sum(stages.values()) ...}`. Предпочтительно посчитать в Python.

4. (Опц.) Растянуть график активности до окна периода: сейчас `_activity` жёстко 7 дней
   (`analytics.py:42-52`) независимо от `period`. Для `30d`/`all` можно показывать 30 дней.
   Не обязательно к этой итерации.

## Тесты (обязательно)
В тест-модуле аналитики/скоупа:
1. `require_full_admin`: сессия админа (`_manager_bot_scope → None`) проходит; скоуп-менеджер
   (напр. login `medina`) → `HTTPException(403)`; незалогинен → 401.
2. `compute_analytics.by_manager[*]` содержит `won_rate`, `avg_response_min`, `share`; арифметика
   верна на фикстуре (напр. менеджер с 2 handled / 1 won → `won_rate == 50`).
3. `funnel_totals` (если добавлен) = сумма стадий по воронке.
4. Регресс: страница `/analytics` для админа рендерится 200; для скоуп-менеджера — 403.

## Приёмка
- Скоуп-менеджер НЕ видит аналитику (ни ссылки, ни по URL — 403).
- Админ видит: график по сотрудникам (бары + win-rate + время ответа), containment-донат,
  сплит по воронкам — всё инлайн, без внешних запросов.
- Существующие панели (Сегодня, исходы, активность, воронки, причины) не сломаны.
- pytest зелёный.
