# E5-01C — поиск по исходному PDF

09.10.2026. STANDARD / solo. Локальный поиск для проверки специалистом реализован;
допуск к автоматическим ответам клиенту остаётся отдельной незавершённой задачей.

В карточке анкеты ссылка «Поиск по исходному PDF» открывает
`/admin/kg-entry/knowledge`. Действуют прежние full-admin, workday и выключенный
по умолчанию `ADMIN_KG_ENTRY_ENABLED`. Источник читается только после проверки прав;
БД, LLM и сеть для поиска не нужны. Общий поиск не получает данных контакта.

`app/knowledge/retrieval.py` проверяет закреплённые SHA-256 PDF/Markdown и метаданные
source-lock, заново собирает корпус и сравнивает его с сохранённым артефактом.
Это проверка происхождения и целостности, не независимая юридическая сверка текста.
Поле `retrieval_connected=false` исходного corpus.json описывает артефакт подготовки;
его не меняет запуск этого локального поиска. Оно не является runtime-флагом маршрута.
CRLF checkout поддержан. Изменение текста, страниц, разрешения публикации, пропуск
или дублирование фрагмента блокирует загрузку. Источник задаётся приложением,
пользовательский запрос не может указать путь. Проверка выполняется при каждом чтении.

Индекс покрывает ровно 74 фрагмента блоков 1–2, 5–13, 15–17, указанных IT-инструкцией
на стр.2 PDF. Ранжирование лексическое: частоты терминов, вес заголовка, стабильный
порядок равных результатов, короткие русские основы и небольшой словарь EN→RU.
Это не семантическая модель; сложный запрос может потребовать переформулировки.
Численный score — вес совпадения, не уверенность AI или вероятность применимости.

Запрос до 200 символов / 40 уникальных терминов, результат до 10 фрагментов (UI — 5),
опциональный фильтр блока. Полный текст с контекстом и таблицами остаётся доступен;
источниковые метки, вопросы SRC, страницы по маркерам конверсии, строки, хеши
сохранены. Выдача всегда `review_only`, `may_quote=false`, `publication_approved=false`.
Копия результата не меняет индекс. В UI текст Markdown отображается как исходник,
HTML не исполняется. Нет стороннего Markdown renderer или внешних ресурсов.

CLI из любого рабочего каталога:

```powershell
python scripts/search_kg_knowledge.py "семья" --block 10 --limit 3
```

Dockerfile копирует только нужный Markdown и два файла корпуса; `.dockerignore`
разрешает этот конкретный документ. Остальные отчёты/архивы docs в образ не добавлены.
Фактическая Docker-сборка отдельно отражается в evidence, не предполагается из COPY.

Проверки: `tests/test_kg_retrieval.py` (реальный зафиксированный корпус, поисковые темы,
повреждения, дубликаты, caps, CLI, CRLF), `tests/test_admin_kg_knowledge.py` (роли,
флаги, отсутствие SQL, ошибки, XSS), браузерный сценарий с JS и без JS.
Публикация знаний, бот-ответы и оценка их качества по Б.8 не выполнены этим поиском.
