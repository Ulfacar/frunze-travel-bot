# E6-01B — общая сводка заявителей и текущих заявок

10.10.2026 · STANDARD / solo · локальное изменение для просмотра.
Путь: визовая услуга → анкета въезда → заявители и подачи → **Сводка группы**.
Основание: §14.1 исходного PDF, физическая страница63, повторно сверенная с оригиналом.

## Правила сводки

Каждая отдельная процедура образует цепочку попыток. В общий прогресс входит её
последняя попытка, даже если она закончилась отказом или закрытием. Прежняя попытка
перестаёт быть текущей только при наличии проверенной связи на следующую. Независимые
заявки одного человека на один вид документа остаются отдельными цепочками.

Сводка охватывает всех зарегистрированных людей и все попытки услуги, включая те,
которые не видны на первой странице реестра. История не удаляется. Общие счётчики:
люди, люди без заявок, текущие заявки, прежние попытки, все попытки; отдельно шесть
состояний журнала и четыре семейства процедур.

| Ситуация в журнале | Общая надпись |
|---|---|
| Людей нет | Заявители ещё не добавлены |
| Хотя бы один человек без заявок | Есть заявители без заявок |
| Есть доработка, отказ или закрытие текущей попытки | Есть заявки, требующие внимания |
| Есть черновик | Есть неподанные заявки |
| Есть подача на рассмотрении | Ожидаются решения |
| Все текущие заявки одобрены, людей без заявок нет | Одобрения записаны по всем текущим заявкам |

Это порядок информационных надписей, не новый порядок юридических стадий. Все
счётчики показываются одновременно: заголовок о недостающих заявках не прячет отказы.
Кнопки фильтруют людей; у найденного человека видны все его текущие процедуры.
По20 людей на странице; старый номер страницы ограничивается последней доступной.
Итоги сверху всегда относятся ко всей услуге. Печать явно содержит фильтр, диапазон
людей, номер страницы и время UTC; это печать текущей страницы, не всей большой группы.

Одобрение не означает проверку/передачу документа, готовность к поездке, полноту
необходимого набора процедур или завершение услуги. Закрытие без завершения остаётся
сигналом внимания; его нельзя автоматически считать успехом. Старый ServiceCase
и его этап не меняются. Исполняемые V/W/R/**U** процессы ещё не опубликованы:
в оригинале урегулирование использует U01–U09, а L — тип выездной визы.

## Реализация и ограничения

- `app/domain/entry_group_overview.py`: чтение согласованной группы, проверка всех
  связей и полной истории через общий валидатор E6-01A, агрегирование и фильтры.
- PostgreSQL: shared lock услуги препятствует добавлению людей/попыток; shared locks
  всех заявок по ID препятствуют смешиванию поколений событий/reference. SQLite:
  явный BEGIN в существующем transaction wrapper. PG runtime здесь не подтверждён.
- Шесть SELECT независимо от размера группы; ограничены люди (1000), попытки (2000),
  события (20000). При превышении показывается503 с переходом в обычный реестр,
  без усечённого итога. Эти пределы ограничивают только обзор, не создание заявок.
- GET использует прежние named full-admin/KG-OFF/workday gates. Включённая запись
  для просмотра не нужна. Никаких SQL-записей, новых таблиц, изменения прав или
  автоматических действий. Заголовки no-store/no-referrer.
- Ошибки и повреждённые связи закрывают итог целиком. Детали исключений и чужие
  данные не попадают в ответ; стандартные логи содержат только фиксированную причину.

Новые тесты проверяют две независимые процедуры/повтор, скрытые пагинацией заявки,
людей без заявок, отказ/доработку/закрытие, все одобрения, фильтры, чужую услугу,
лимиты, повреждение прежней истории, одновременное чтение/запись и отсутствие SQL
изменений. Браузер — mobile390 JS / desktop1365 без JS, ссылки, focus, печать.
Точные результаты и ревизия: текущий handoff из `ai/STATE.md`.

Независимые CRITICAL review/audit/PG для предшествующего E6-01A остаются открытыми.
Этот STANDARD экран и SELF_REVIEW не закрывают их. Весь PDF не завершён; следующие
участки — подтверждённые процессы/обязательные факты, профили/документы, сопровождение
и диалог. Нового точного процента готовности нет.
