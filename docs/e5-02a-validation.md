# E5-02A — проверка файлов перед импортом

Первый исполняемый этап E5-02, 06.10.2026. Автор — Codex по просьбе Алана продолжить
работу Claude. Исходный проект — [E5-02](e5-02-slots-schema.md).
Это локальная библиотека и CLI. Они не подключены к боту, админке или БД.
Полный E5-02 (хранилище, импорт черновика, утверждение, публикация/откат) ещё не реализован.

## Запуск

Зависимости добавлены в `requirements.txt`: `jsonschema>=4.26,<5`, `PyYAML>=6.0.3,<7`.

```powershell
python scripts/validate_kg_entry.py bundle tests/fixtures/kg_entry/synthetic_bundle --source tests/fixtures/kg_entry/synthetic_source.txt
python scripts/validate_kg_entry.py slots tests/fixtures/kg_entry/synthetic_slots.json --countries tests/fixtures/kg_entry/synthetic_bundle/countries.yaml --profile handoff --today 2026-10-06
python -m pytest tests/test_kg_entry_validation.py -q
```

Примеры **синтетические**: цифры намеренно не повторяют законодательство и не должны
попасть в боевую базу. `confirmed` в примере тестирует формат поля, не подтверждает норму.
CLI возвращает JSON, exit 0 при успешном preflight, 1 при ошибке данных, 2 при неверных
аргументах. Успех содержит `imported: false` и предупреждение `preflight.not_approval`.
Значения анкеты и контакт не печатаются. Ошибки: код, файл/JSON pointer, описание ограничения.
Синтаксические ошибки YAML обычно содержат строку/колонку; duplicate key JSON — имя файла.

## Анкета

`app/knowledge/schemas/kg-entry-slots-v1.json` — Draft 2020-12 из проекта §2.3.
`slots_schema(profile)` отдаёт копию схемы, `validate_slots(data, context=..., profile=...)`
выполняет проверку форматов, условий и семантики. Профили `collecting` и `handoff` соответствуют
§2.4. Различаются отсутствие поля, `unknown`, `not_applicable`, конкретное значение; null запрещён.

`SlotContext` требует явные `countries` и `today`; CLI по умолчанию берёт дату Asia/Bishkek.
Справочник — входные данные, не встроенная таблица юридических правил. S5/S6 получают
опциональные списки применимости из контекста; если их нет, результат содержит предупреждение,
а не выдуманное решение. CLI эти списки не задаёт.

- S1/S2/S4/S9: даты, гражданство/паспорт, интервалы и известность стран проверяются.
- S3: истёкший паспорт даёт `report.stop_factors = ["passport_expired"]`, не отклоняет анкету.
- S7: входные `decision` **и** `stop_factors` запрещены независимо от `readOnly` в схеме.
  Здесь нет параметра `writer="calculator"`, которым вызывающий мог бы обойти проверку.
- S8: успешный `prepared_slots` — глубокая копия без `contact`; при ошибке — `None`.
  Это подготовка, а не сохранение, не передача человеку и не удаление ПДн из других мест.
- Это не полный расчёт стоп-факторов E5-03. Признаки доверия к истории/доказательствам
  при будущем сохранении необходимо задавать сервером по §3.4, не принимать из анкеты.

Уточнения проекта: в enum добавлен уже предусмотренный S3 `passport_expired`; для
`entry_point_other` запрещены пустая строка и пробелы. Дополнительно проверяются пары дат
события и прошлых виз. Экспорт схемы сам по себе не заменяет `validate_slots`.

## Пакет `kg-entry-bundle/1`

Каталог содержит ровно три обычных файла: `meta.yaml`, `countries.yaml`, `units.yaml`.
Ссылки-файлы не принимаются. JSON допустим внутри `.yaml` как подмножество YAML; файлы
анкеты с расширением `.json` проверяются также по грамматике JSON.

`meta.yaml` содержит обязательные:

```yaml
schema_version: kg-entry-bundle/1
set_code: kg_entry
version_label: author-assigned-label
source_document: author-assigned-source-name
source_hash: <64 lowercase hex SHA-256 characters>
prepared_by: author
prepared_at: '2026-10-06T12:00:00+06:00'
```

Опционально `effective_from` (дата или null). `source_hash` относится к **байтам файла**,
переданного `--source`, например PDF. `bundle_hash` в отчёте — отдельный SHA-256
нормализованного пакета. Это разрешает неоднозначность исходного проекта между §1.1/§5.
Имя источника не используется как путь и не загружается из сети.

`countries.yaml` — alias → ISO3. Алиасы нормализуются NFKC, casefold, пробелами;
коллизии и подмена канонического кода отклоняются. ISO3 определяется по реестру этого
пакета, а не только regex. Проверки реестра на полноту/официальность здесь нет.

`units.yaml` — плоский массив единиц. Обязательные поля:
`unit_id`, `kind`, `title`, `section`, `page`, `source_ref`, `label`, `confirmation_status`,
`value`, `value_schema_version: 1`, `owner`. Полный контракт и 12 схем value —
`app/knowledge/bundle_schema.py`. Неизвестные поля и вложенная структура Б.5 отклоняются.
Текстовые условия `requires/condition/action/anchor` остаются данными и не исполняются.

Уточнения контракта для реализации:

- `prepared_at`, `verified_at`, `review_due_at` — RFC 3339 с часовым поясом;
  `effective_from/to` — календарные даты. `verified_at/by` задаются вместе.
- `registration_default.value.not_in_list` обязателен, включая пустой массив.
  На каждую страну visa-free нужна отдельная exemption-единица любого статуса **или**
  запись not_in_list, но не обе. `registration_term` exemption не заменяет.
- `blocked` требует null value + непустой объект blocked_value + conflict_ref.
  `decision_pending` требует null value + blocked_value. Неутверждённая цена
  остаётся внутри blocked_value. `needs_verification` с неизвестным value тоже
  должен сохранять доказательства в blocked_value. `confirmed` с конфликтом отклоняется.
- Списки стран принимают алиасы и преобразуются в ISO3; исключения остаются отдельными
  единицами. Дубли ID, повтор страны через разные алиасы и перекрытия обычных visa-free
  групп отклоняются. Условные исключения оформляются special_regime.
- `rule_param` проверяет соответствие bool/list/целого числа единице измерения;
  list — список непустых строк. Для special_regime `requires` — текст.
- Шаблон использует только `{simple_name}`, с точным перечнем placeholders; числовые
  литералы вида `30 дней` отклоняются. Это не семантическая/юридическая проверка текста:
  числа словами и правильность формулировок требуют отдельного ревью E5-04.
- Хеш не меняется от порядка единиц, ключей и стран. Блокированные данные, метки,
  источники и авторские значения сохраняются, отсутствующие одобрения не добавляются.

Разбор запрещает дубликаты ключей, YAML anchors/aliases/явные tags, нечисловые NaN/Infinity,
некорректный Unicode. Inline-комментарии в units запрещены, включая комментарии после
`|`/`>`; `#` внутри строки/текста блока остаётся текстом. Bool — только true/false;
числа — десятичная JSON-запись, без молчаливого преобразования `012`, `0x10`, `1:20`.
Пределы: 2 MiB на файл, 32 уровня, 50 000 узлов, целое число до 512 бит,
5000 единиц, исходный файл до 128 MiB.
