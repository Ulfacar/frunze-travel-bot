# Спека: Календарь менеджера = дожим-движок в мессенджере

Составлено 27.07.2026 по разговору с Аланом (продуктовое видение). Календарь —
**не планировщик-сетка, а движок дисциплины дожима**, встроенный в утренний бриф.
Цель — починить «дырявое ведро» (157 застойных лидов, медиана ответа 3ч,
конверсия не мерится) и сделать продажи измеримыми.

## Зачем он менеджеру (ценность, не фичи)
1. **Ни один лид не забыт** — каждый незакрытый клиент получает «следующее касание»
   с датой; система помнит за менеджера. Удар по застойным лидам.
2. **Обещание перезвонить — святое** — «перезвоню в 14:00» становится задачей,
   которая пингует. Сдержал слово → доверие → продажа.
3. **Утром — конечный список звонков по приоритету**, а не тревожная лента WhatsApp.
4. **Серия дожима** (туры закрываются со 2–4 касания): касание 2 через 2д, 3 через 5д.
5. **Звонить, когда клиент жив** — касание на его активное время.
6. **Гриша впервые видит работу** — открытые перезвоны, просрочка, воронка касаний
   = измеримость (главная цель пилота).

## Форм-фактор (иначе не взлетит)
Менеджеры живут в телефоне, красивую сетку день/неделя открывать НЕ будут.
Поэтому сила календаря — через **утренний бриф в Telegram + кнопки в один тап**
(«перенести на завтра», «сделал», «+2 дня»). Грид день/неделя — вторично, скорее
для Гриши-обзора. Правило: совпасть с привычкой (мессенджер), иначе будет как
Bitrix — «есть, но не пользуются».

## Что УЖЕ есть (проверено в коде 27.07)
- Домен `CalendarTask` (kind, scheduled_date, scheduled_at, manager_id, contact,
  created_by, ai_summary), сервис create/reschedule/complete/cancel + аудит-события.
- Экран `/admin/calendar` (день/неделя) + блок «Задачи» в карточке клиента.
- Менеджер ВРУЧНУЮ: создать задачу-звонок (дата+время), перенести, закрыть, отменить.
  Владение соблюдается (`_manager_can_touch_task`).
- Утренний бриф (`calendar_brief`) ЧИТАЕТ задачи дня и показывает «⏰ 14:00 …».
- Флаги на проде ON (27.07): calendar_brief_enabled, tours_pilot_assign_enabled и др.

## Чего ПОКА НЕТ (доработки — двусторонняя связка бот ↔ календарь)
1. **Бот → календарь (авто-задача).** Триггер: бот ночью квалифицировал горячего /
   пообещал «менеджер перезвонит утром» → сам создаёт задачу-звонок на утро в
   календарь владельца, с контекстом (направление, бюджет, последний вопрос),
   created_by='bot'. Домен и поле created_by уже готовы под это.
2. **Календарь → бот (чтение как контекст).** Бот видит назначенный звонок на 14:00
   → не дёргает клиента лишний раз / отвечает «наш менеджер свяжется в 14:00».
   Сейчас агент/оркестратор календарь НЕ читают (0 ссылок).
3. **Серия дожима** — авто-каскад касаний (2д/5д) со стоп-условиями. Пересекается
   с фичей followup/дожим (пока OFF). НЕ авто-серия в календаре сейчас.
4. **One-tap в Telegram** — кнопки «перенести/сделал» прямо в брифе (callback_query)
   вместо deep-link в /admin/morning. Отложенный webhook-подпроект (+1–2 дня).

## Предлагаемая очерёдность
- **Шаг 0 (сейчас, живо):** обкатать РУЧНОЙ календарь на Адеми в пилоте —
  ставит звонки, бриф показывает, отмечает исход. Собрать её фидбэк.
- **Шаг 1:** бот → авто-задача на горячих ночных (наполнение без ручного труда).
- **Шаг 2:** бот ← чтение календаря (не дёргать, если звонок назначен).
- **Шаг 3:** one-tap кнопки в Telegram + серия дожима.
