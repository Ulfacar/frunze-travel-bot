сверен на физических стр.27, 74–75. История относится к фактическим пересечениям

Путь: визовая услуга → анкета въезда → «История поездок в Кыргызстан».
История общая для контакта; отдельные Applicant/Application этим этапом не созданы.
Номера паспортов, ФИО, сканы и свободный текст не добавлены. Никакие разрешённые дни,
право въезда или юридическая проверка из введённых дат автоматически не выводятся.

## Поведение

- Фактические въезд/выезд, основание, страна паспорта, источник и факт проверки.
  Полнота истории различает неизвестное, неполное и полное. Полная пустая история
  требует отдельного подтверждения отсутствия поездок.
- Открытый интервал требует явного ответа «Ещё в Кыргызстане». Неизвестная дата
  выезда не превращается в продолжающееся пребывание: сохранение такой строки
  отклоняется с сохранением ответов в форме. Для таких фактов нужен будущий draft-слой.
- Будущие/перевёрнутые даты, два открытых интервала и подтверждение только со слов
  клиента отклоняются существующим доменным сервисом. Пересечения закрытых поездок
  остаются видимыми с предупреждением; пересечение границы в один день не удаляется.
- Сохраняется целиком новая неизменяемая версия через существующий StayHistory.
  Исключение поездки действует только для следующей версии; старые записи остаются.
  Все 1000 допустимых строк сохраняются без скрытого обрезания. Добавление строки
  работает без JavaScript и само по себе ничего не пишет в БД.
- Существующая непрозрачная связь с паспортом сохраняется на сервере, не попадает
  в HTML и не принимается из формы. Смена страны или явная отметка о смене паспорта
  убирает эту связь только в новой версии.
- Новую историю можно явно выбрать для следующей проверки. Сохранение истории
  не меняет готовые анкеты. Старые карточки/печать показывают закреплённые поездки
  и ссылку именно на их версию. Выбор сохраняется после ошибки анкеты.

## Защита и восстановление

Прежние full-admin/workday/default-OFF/write gates. Новых ролей/разрешений нет.
URL: `/admin/case/{case_id}/kg-entry/history`, GET и POST; GET без SQL-записи.
CSRF и HMAC связывают actor, case, contact, base revision, дату и ключ запроса.
Ограниченный URLencoded POST, строгие поля/enum, отсутствие дублей и пропущенных
сохранённых строк. CAS отклоняет устаревшую вкладку; одинаковый повтор возвращает
сохранённую версию, потерянный ответ после commit восстанавливается тем же ключом.

Чужая/повреждённая история не показывается. Ошибка хранения сохраняет проверенную
форму для повторной отправки; новый ключ не генерируется незаметно. Ответы no-store,
no-referrer; Jinja экранирует значения. Каталог ISO3 включён отдельным COPY Dockerfile;
он служит выбору страны, а не подтверждению визового режима. Миграций нет.
