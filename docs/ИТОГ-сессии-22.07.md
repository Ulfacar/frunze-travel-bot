## 5. Sprint 2 «Живые права/назначения» — РЕАЛИЗОВАН

### Архитектурные решения (все 4 приняты Аланом сегодня)
1. **Источник правды владения — доменный `Assignment`** (история+ревизии), панельный
   `assigned_to` — зеркало. Почему: в Sprint 3 именно домен поедет в Bitrix-синк,
   панельная строка выброшенной работой не станет.
2. **Автозахват ничьего лида отправкой** (ответил первым — твой), чужие — блок.
   Почему: не ломает темп менеджеров лишним кликом.
3. **Round-robin виз на ПЕРВОМ входящем.** Почему: детерминированно, ни один лид
   не висит ничьим.
4. **TG-пуш менеджеру при назначении — сразу** (труба `telegram_chat_id` из Sprint 1).

### Что написано
- `app/core/live_authz.py` — сборка WP3-`Actor` из cookie-сессии; направления команды
  выводятся из существующего `BOT_SCOPE_BY_MANAGER` через сценарии ботов (новой
  конфигурации НЕ появилось). Флаг `authz_enforce_enabled` (default OFF).
- `app/domain/live_assign.py` — операции владения под row-lock контакта
  (`SELECT..FOR UPDATE`, PG сериализует гонку двух менеджеров — закрыт обещанный
  WP3-лок; на SQLite no-op). `end_active` для release (история сохраняется).
- `app/domain/autoassign.py` — round-robin виз: флаг `visa_autoassign_enabled`
  (default OFF), только direction=visa, идемпотентно на контакт (фактически — первое
  входящее), выбор `select_next_visa_manager` (LRA, `manager_off:<login>` уважается),
  назначение от `system` под локом, зеркало в панель ТОЛЬКО если там пусто, личный
  TG-пуш (без chat_id — тишина), бота НЕ перехватывает, fail-safe (живой диалог
  не страдает никогда), PII в логи не пишется.
- `app/core/orchestrator.py` — один вызов `maybe_autoassign` в `_log_in` (рядом с
  shadow-мостами, тот же best-effort блок).
- `app/admin/router.py` — `_ownership_guard` на `takeover`/`send`/`release`/
  `buyers_claim`: владелец работает как раньше; сосед получает «Диалог ведёт X —
  перехват запрещён»; админ на чужом лиде получает «сначала Переназначить» (правило
  M3 — админ не пишет чужим без переназначения на себя); ничей лид закрепляется за
  первым действием. Легаси-`assigned_to` из панели уважается как владелец и лениво
  мигрирует в домен при первом действии владельца. Fail-open при сбое домена
  (осознанно: это дисциплина команды, не граница безопасности — панель не должна
  лечь из-за домена; сбой виден в логах).
- Новый эндпоинт `POST /conversation/{id}/reassign` — только полный админ, работает
  и БЕЗ флага (пишет домен + зеркалит панель, аудит `reassign`).
- UI: бейдж владельца на карточках канбана (раньше владельца на доске не было
  вообще), фильтр «Мои лиды» (`?mine=1`, переживает авто-обновление), дропдаун
  «Переназначить» у полного админа, тумблеры «Очередь авто-распределения виз»
  (`manager_off:<login>`) на системной странице.
- Флаги в админ-тумблеры: «Жёсткое владение лидами», «Авто-распределение визовых
  лидов» — включаются из панели без рестарта.

### Чего НЕ делалось (по договорённостям)
Bitrix не тронут; source-of-truth не переключался; оба новых флага default OFF —
деплой сам по себе ничего не включает; скоуп менеджеров остался fail-closed.

### Ревью (codex-reviewer): 0 CRITICAL, 1 HIGH, 2 MEDIUM, 2 MINOR, 1 NIT — ВСЁ исправлено
- **HIGH**: Telegram from.id гнался через `normalize_phone` → 9-значный id молча
  превращался бы в выдуманный номер `996XXXXXXXXX` (ложный Contact), другие длины —
  в DomainError→fail-open (защита тихо не включалась на TG-лидах). Фикс: канало-
  зависимая идентичность (`identity_for`: whatsapp→phone, telegram→telegram-id без
  нормализации) во всех новых точках (guard, reassign, autoassign).
- **MEDIUM**: гонка «двое жмут перехват»: проигравший получал fail-open (DomainError
  из-под лока глотался общим except) и перетирал панельное зеркало. Фикс: DomainError
  = честный отказ («Диалог только что взял другой менеджер»), fail-open — только
  инфра-сбои.
- **MEDIUM**: чтение флага `authz_enforce_enabled` было вне try — сбой app_flags
  ронял бы takeover/send для всех. Фикс: обёрнуто, fail-open.
- **MINOR**: повторный клейм своим владельцем плодил ревизии Assignment. Фикс:
  short-circuit без записи. **MINOR**: buyers_claim показывал владельца из устаревшей
  панели. Фикс: сообщение из guard (доменная правда). **NIT**: описание флага
  уточнено (админ может и перехватом).
- +4 теста на фиксы (TG-идентичность в guard и autoassign, гонка → отказ, re-affirm
  без мусора). Финал: **511 passed, 1 skipped на SQLite И PostgreSQL 16**.
