## Часть II. План разработки (workstream'ы)

### WS-0. Предполётные фиксы кода (до деплоя, ~1 час)
1. **Флаги под full-admin**: `/admin/flags/{key}` → `require_full_admin`
   (страницу флагов и так видит только полный админ; пер-бот тумблеры
   `/bots/{id}/toggle` НЕ трогаем — девочки включают/выключают ботов сами,
   это требование Гриши). + тест: скоуп-менеджер получает 403.
2. Прогон полного сьюта (SQLite) — коммит — пуш.

### WS-1. Деплой ветки на прод (чт, ~2 часа, по ранбуку)
Порядок (каждый шаг — с проверкой):
1. **Бэкап**: `pg_dump` БД frunze + tar рабочей директории приложения.
   Заодно поставить **ежедневный pg_dump-крон** (7 дней ротации) — бэкапа
   не существует с запуска 01.07, это черная дыра.
2. Залить файлы ветки (деплой файлами, как всегда; прод не git).
3. `alembic upgrade head` — создаст ТОЛЬКО новые таблицы (контакты, заявки,
   назначения, сообщения-леджеры, календарь). Легаси-таблицы не трогаются
   (доказано тестом). Откат: `alembic downgrade base` сносит только новые.
4. Прописать `WEBHOOK_SECRET` в prod.env + `?s=` в вебхуке Wappi.
5. Рестарт строго `-f docker-compose.vps.yml --env-file prod.env`
   (иначе MANAGERS слетают — известные грабли).
6. Smoke: /health, логин в админку, /admin/calendar открывается, Wappi-входящие
   идут, Bitrix-зеркало живо, в логах нет ошибок. Все новые флаги OFF →
   поведение прода не изменилось.

### WS-2. Конфигурация пилота (чт–пт)
1. **`telegram_chat_id` менеджеров** — единственное, что нужно от людей.
   Запросить у Гриши/девочек сразу (написать каждому боту-брифов /start,
   взять chat_id). Без chat_id бриф просто не шлётся — безопасно.
2. Включить `calendar_brief_enabled` (бриф пойдёт только тем, у кого есть chat_id).
3. Включить `authz_enforce_enabled` — жёсткое владение (пилотная группа = все,
   т.к. затрагивает только действия менеджеров в панели; поведение для
   единственного владельца не меняется).
4. `visa_autoassign_enabled` — пока OFF (включим, когда девочки-визовички
   реально начнут работать через панель/подтвердим ростер).

### WS-3. Визовый бот КГ по СОП Марселя (пт–сб, после получения СОП)
1. Дождаться файла СОП от Марселя. До файла — заготовка по надиктованному:
   - Ветка квалификации: цель поездки → (туризм | бизнес) → свои цепочки вопросов.
   - Выход менеджеру: гражданство, цель, даты, кол-во, документы, срочность.
   - Вилка стран высокого риска (Индия/Пакистан/Бангладеш/Африка) — консультация,
     без гарантий (политика «не обещать» уже в промптах).
   - Цена — только по запросу; срочная (2 дня) vs стандартная (5 дней) — уточнить
     цены у Марселя; НЕ выдумывать (валидатор + промпт).
   - Стиль: короткие сообщения, по 1–2 вопроса за ход (анти-«поэмы»),
     дожать до офиса/звонка.
2. Реализация: обновить `visa.py` промпт (сценарий КГ) + FAQ-сиды. Это визы
   В Кыргызстан = воронка Марселя; НЕ трогать существующий скоуп GetVisa
   (США/Шенген…) — уточнить у Алана, тот же бот `getvisa` или отдельный bot_id
   на новом Wappi-номере Марселя (истории там не будет — чистый лист).
3. Прогнать через тренажёр `scripts/run_scenarios.py`: сценарии «туризм»,
   «бизнес», «Пакистан» (риск-вилка), «сколько стоит», «срочно за 2 дня».

### WS-4. Тесты вживую (сб–вс)
1. Самопрокрутка: тестовые диалоги через TG-песочницу (`frunze_tours_tg`,
   `getvisa_tg`) — квалификация, календарь-задача из карточки, бриф утром.
2. Проверить бриф на живом chat_id (свой аккаунт), затем менеджерские.
3. Панель: перехват/владение — два логина, чужой лид блокируется, «Мои лиды».
4. Мониторинг логов сутки: ошибок 0, wappi идёт, зеркало идёт.

### WS-5. Запуск (пн 27.07)
1. Утром: включить ботов по списку Гриши («батарейки»), убедиться что бриф ушёл.
2. Показать Грише: календарь, бриф в TG, владение лидами; и где в Bitrix
   смотреть переписку (Лид → Таймлайн) — снять «зеркалка не работает».
3. Наблюдение весь день; rollback-план: выключить флаг/бота — секунды,
   код откатывать не нужно.

### После пилота (порядок из стратегии)
1. **Sprint 3 — Bitrix 2-way для виз**: ответы из Bitrix → к нам, общая история
   (inbox/outbox уже в живом потоке), dedup/anti-loop включаются, Deal won
   читается назад = продажи наконец меряются. Блокеры — 3 вопроса Грише (выше).
2. **Дожим**: формулировки утверждены (визовый пинг — после ОК Гриши),
   тренажёр → включение на 1 боте.
3. Финальный review Opus → широкий rollout.
4. Очередь №2: воркер-бот Марселя (отдельный номер уже куплен).
5. Потом: STT, атрибуция рекламы, аналитика.

## Часть III. Риски и как их гасим

| Риск | Митигция |
|---|---|
| Миграция на проде пойдёт не так | PG16-валидация пройдена (up/down/up чисто); бэкап перед стартом; downgrade сносит только новые таблицы |
| Деплой сломает текущих ботов | Флаги OFF = поведение байт-в-байт прежнее (закрыто тестами); smoke-чеклист |
| СОП Марселя придёт поздно | Заготовка по надиктованному уже в плане; визы КГ можно включить позже основного запуска — это отдельный флаг бота |
| Бриф уйдёт не туда | Без chat_id не шлётся вообще; chat_id только из env; в общую группу не падает by design |
| Менеджеры запутаются во владении | Включаем authz с объяснением; сообщения в UI человеческие («Диалог ведёт X…»); rollback = выключить флаг |
| TourVisor/OpenRouter кончатся | Оба оплачены на встрече; watchdog-алерты живы |
| «Бот думает что январь» (жалоба Гриши) | Уже починено хотфиксом 09.07 (инъекция даты) — на проде ЕСТЬ; подтвердить Грише |
