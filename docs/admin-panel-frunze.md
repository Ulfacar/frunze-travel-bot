# Админ-панель Frunze Travel: канбан диалогов и AI-агент

Цель: дать менеджеру CRM-подобную панель, где каждый входящий диалог виден как карточка в канбане, а внутри карточки доступен полный контекст переписки, квалификация клиента, действия AI-агента и ручной перехват менеджером.

## Основная модель

Админка не должна быть отдельной "витриной лидов". Это рабочее место менеджера:

- слева канбан-доска по выбранному направлению;
- справа полное диалоговое окно с клиентом;
- карточка двигается по стадиям автоматически, но менеджер может перехватить диалог;
- бот всегда сохраняет весь контекст: сообщения клиента, ответы бота, ответы менеджера, собранные поля, рекомендации и причину эскалации.

В MVP нужны три отдельные доски:

1. `visa` - визы.
2. `tours` - туры.
3. `tickets` - билеты.

В интерфейсе это лучше делать вкладками, чтобы менеджер не смешивал разные типы продаж.

## Колонки канбана

Базовые стадии подходят для всех направлений:

| Стадия | Что происходит |
| --- | --- |
| Новый | Клиент только написал, бот определяет направление и начинает приветствие. |
| Квалификация | Бот задает группу вопросов и собирает данные. |
| Подбор / оценка | Для туров - поиск через TourVisor. Для виз - оценка шансов. Для билетов - сбор маршрута и параметров. |
| В офис / консультация | Клиент сложный, высокий чек, риск по визе или нужен человеческий контакт. |
| У менеджера | Менеджер перехватил диалог и дожимает клиента на оплату/встречу/созвон. |

Позже эти стадии нужно связать с точными стадиями Bitrix24, чтобы движение в админке синхронизировалось со сделками.

## Полный контекст карточки

Внутри карточки обязательно показывать:

- всю переписку по времени: клиент, бот, менеджер;
- канал и идентификатор клиента: WhatsApp/Telegram/Bitrix Open Lines;
- направление: `visa`, `tours`, `tickets`;
- текущую стадию и статус: бот ведет / менеджер перехватил;
- собранную квалификацию;
- последнее сообщение и сколько клиент ждет ответа;
- заметки AI-агента: что понял, какие риски увидел, что рекомендует менеджеру;
- историю системных действий: поиск тура, оценка визы, создание/обновление сделки в Bitrix24.

Главное правило: менеджер не должен спрашивать клиента заново то, что клиент уже сказал боту.

## Воронка "Туры"

### 1. Приветствие и вопросы

Бот приветствует клиента и собирает минимум:

- город вылета;
- страна/курорт;
- даты или диапазон дат;
- количество ночей;
- состав туристов: взрослые/дети и возраст детей;
- бюджет;
- звездность отеля;
- питание;
- пожелания: первая линия, семейный отель, молодежный отдых, спокойный отдых;
- телефон/имя, если еще не известны.

### 2. TourVisor

После сбора параметров бот вызывает TourVisor API:

- ищет актуальные туры по параметрам клиента;
- сортирует сначала по соответствию бюджету и качеству;
- возвращает клиенту 2-4 понятных варианта;
- сохраняет в карточку параметры поиска и выбранные варианты.

Если данных не хватает, бот не должен делать слабый поиск. Он задает уточняющий вопрос и только потом идет в TourVisor.

### 3. Эскалация

Бот зовет в офис или подключает менеджера, если:

- клиент не определился и мечется между направлениями;
- бюджет сильно не совпадает с ожиданиями;
- клиент требует гарантий, скидок или "самый дешевый без разницы";
- есть сложный состав туристов;
- клиент горячий и готов платить;
- клиент задает вопрос, где нужен человеческий дожим.

## Воронка "Визы"

### 1. Приветствие и вопросы

Бот собирает:

- страна визы;
- цель поездки;
- даты поездки;
- были ли отказы;
- визовая история;
- работа/доход;
- семейное положение;
- наличие приглашения/броней;
- кто оплачивает поездку;
- срочность;
- город клиента и удобство офиса/созвона.

### 2. Оценка шансов

Бот дает ориентировочный процент шанса, но формулировка должна быть аккуратной:

- это предварительная оценка, не гарантия;
- процент объясняется 2-4 факторами;
- если кейс рискованный, бот не спорит, а зовет на консультацию.

Пример логики:

- сильный кейс: 70-90%, зовем на подготовку документов;
- средний кейс: 45-70%, предлагаем консультацию;
- рискованный кейс: до 45%, зовем в офис/на созвон и не обещаем результат.

### 3. Эскалация

В офис или к менеджеру сразу:

- прошлые отказы;
- слабые финансы;
- нет работы/подтверждений;
- сложная страна;
- клиент просит гарантию;
- срочная подача;
- несовпадения в ответах.

## Воронка "Билеты"

Пока отдельная доска нужна, даже если автоматизация слабее туров:

- откуда и куда;
- даты;
- one-way/round-trip;
- пассажиры;
- багаж;
- гибкость по датам;
- бюджет;
- телефон/имя.

Если нет прямого API для билетов, бот квалифицирует клиента и переводит карточку в "У менеджера".

## Bitrix24

Bitrix24 должен быть не просто местом хранения, а системой синхронизации сделок.

Минимальный набор действий AI-агента:

- создать лид/сделку при первом качественном обращении;
- выбрать воронку: визы, туры, билеты;
- обновлять стадию при движении карточки;
- писать комментарий с кратким summary диалога;
- сохранять квалификационные поля;
- ставить ответственного менеджера;
- создавать задачу "перезвонить" или "пригласить в офис".

Важно: внутренний источник полного контекста - наша база диалогов. Bitrix24 получает summary, поля и ссылку/идентификатор диалога, но не должен быть единственным местом хранения переписки.

## AI-агент

AI-агент должен продавать и вести клиента к офису/оплате, но без риска обещаний.

Поведение:

- быстро отвечает и держит живой тон Frunze Travel;
- квалифицирует без длинной анкеты одним сообщением на 3-5 вопросов;
- не делает подбор без ключевых данных;
- по турам использует TourVisor, а не выдумывает цены;
- по визам дает вероятность как предварительную оценку;
- сложных клиентов переводит в офис/созвон;
- горячих клиентов передает менеджеру с полным summary.

## MVP

В первую очередь нужно довести:

1. Канбан по трем направлениям.
2. Полный чат внутри карточки.
3. Перехват менеджером: после ручного ответа бот молчит.
4. Логирование всех сообщений клиента, бота и менеджера.
5. Поля квалификации в карточке.
6. TourVisor для туров.
7. Визовая оценка по понятным правилам.
8. Подготовка структуры для синхронизации с Bitrix24.

## Следующая фаза

- Drag-and-drop карточек по стадиям.
- Назначение менеджера.
- Фильтры: ждет ответа, перехвачено, горячий клиент, направление, канал.
- AI-summary для менеджера перед ручным ответом.
- Автоматические задачи в Bitrix24.
- Двусторонняя синхронизация с Bitrix24 Open Lines.
