## Этап 2 — Дожим + ценовая вилка (СПЕКА ДЛЯ CODEX)

### Проблема
Бот отвечает по сути и «затухает» — не даёт клиенту конкретного следующего шага в офис.
На возражение по цене («дорого», «у других дешевле», «подумаю») — бросает диалог.

### Решение (prompt-first, обратимо флагом)
Единый общий блок промпта `DOZHIM_AND_PRICE_FORK`, который **инъектируется в system
на каждом ходе через флаг** (одна точка: `runner.run_turn`, `system=spec.system`).
Дефолт флага — **OFF**: ничего не меняется на проде, пока Алан не включит для теста на живом боте.

### Ограничения (project gotchas — ОБЯЗАТЕЛЬНО соблюсти)
- **НИКАКИХ скидок/процентов/спец-цен от бота** — «скидки к менеджеру» (`knowledge.py:117`).
  Вилка = «дешевле подберём / менеджер отработает по цене лучше → в офис», НЕ «дам скидку».
- Стиль Frunze: коротко (1–2 фразы, ~300 знаков), без markdown, ОДИН вопрос за ход,
  без длинных тире (см. `common.py` LANGUAGE_AND_ESCALATION).
- Воронка-адаптивность: туры — реально можно подобрать дешевле (`search_tours` over-budget
  fallback уже есть); визы — цена сбора фиксирована, вилка = консультация эксперта, не «дешевле».
- Не давить по кругу: отказ прийти → вежливо оставить дверь + `handoff_to_manager`.

### Текст блока (Claude-дизайн, Алан утверждает формулировки)
Кладётся в `app/agent/prompts/common.py` как константа `DOZHIM_AND_PRICE_FORK`:

```
ДОВЕДЕНИЕ ДО ОФИСА / ДОЖИМ (не бросай тёплого клиента на полуслове):
- ВСЕГДА закрывай ход одним конкретным следующим шагом к офису или менеджеру — с понятной
  выгодой для клиента, а не абстрактным «обращайтесь». Плохо: «если что, пишите».
  Хорошо: «Давайте менеджер подберёт лучший вариант под ваш бюджет — вам удобнее сегодня или завтра?»

ЦЕНОВАЯ ВИЛКА — если клиент сомневается в цене («дорого», «дороговато», «у других дешевле»,
«не потяну», «многовато», «надо подумать», «я сравниваю»): не оправдывайся и НЕ бросай диалог.
1. Признай спокойно: «Понимаю, бюджет важен».
2. Дай выбор из двух выгод (вилка), не обещая скидку:
   — если можно подобрать вариант выгоднее (туры — под меньший бюджет) — предложи это;
   — по цене живой менеджер отработает лучше бота — это твой аргумент завести клиента в офис;
   — если цена фиксирована (визовые сборы) — предложи консультацию эксперта, который подберёт
     оптимальную стратегию под бюджет.
3. Заведи в офис/к менеджеру: escalate_to_office (готов прийти) или handoff_to_manager.
   Дай лёгкий вопрос с ответом «да/нет» или «сегодня/завтра».

НИКОГДА не обещай конкретную скидку, процент или спец-цену — это решает только менеджер.
Твоя вилка — не «дам скидку», а «дешевле подберём / менеджер отработает лучше, давайте в офис».
НЕ ДАВИ повторно: если клиент отказался приходить — вежливо оставь дверь открытой и передай
менеджеру (handoff_to_manager), не уговаривай по кругу.
```

### Изменения по файлам
1. `app/agent/prompts/common.py` — добавить константу `DOZHIM_AND_PRICE_FORK` (текст выше).
2. `app/config.py` — `dozhim_enabled: bool = False` в Settings (рядом с followup_* ~136-169).
3. `app/agent/runner.py` — в `run_turn`, перед циклом, вычислить эффективный system:
   `system = spec.system` и, если `await flags.get_flag("dozhim_enabled", settings.dozhim_enabled)`,
   дописать `"\n\n" + DOZHIM_AND_PRICE_FORK`; передавать этот `system` в `messages.create` (стр. 141).
   (Одна точка покрывает ВСЕ воронки — tours/visa/tickets идут через run_turn.)
4. `app/admin/router.py` — добавить `dozhim_enabled` в `FEATURE_FLAGS` (~442) с русским лейблом/описанием,
   чтобы тумблер был в админке.
5. Тесты (`tests/`): (а) блока нет в system при флаге OFF, есть при ON; (б) флаг читается из
   `flags.get_flag` с дефолтом из settings; (в) существующие тесты runner/промптов зелёные.

### Приёмка
- Флаг OFF (дефолт) → поведение бита-в-бит как сейчас (регресс-нейтрально).
- Флаг ON → в system появляется блок дожима; бот на возражение по цене ведёт в офис, скидок не обещает.
- Все тесты зелёные; `codex-reviewer` без критичных находок.

### Вне скоупа этой итерации (следующий заход)
- Детерминированный детектор возражения по цене (как `visa_pricing.PRICE_INTENT_RE`) — если
  промпт-подход окажется слабым.
- Тюнинг follow-up пингов (`branding.FOLLOWUP_PINGS`) под офис-хук.
- Прогон через тренажёр `scripts/run_scenarios.py` на сценариях «дорого → офис».
