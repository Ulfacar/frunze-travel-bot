# СПЕКА для Codex — Content safety bundle (рейсы + рабочие визы)

Автор: Claude (ревьюит). Исполнитель: Codex. Ветка: `feature/token-economy-phase1`. Не деплоить/не пушить/не коммитить.

Цель — убрать два опасных класса ошибок бота:
- **Рейсы (репутация):** бот уверенно заявляет наличие прямых рейсов/чартеров/мест, которых у него нет в данных (реальный кейс: «прямые Бишкек→Египет в июле», клиент поправлял — бот повторяет). НЕ хардкодить Египет — ОБЩЕЕ правило: бот не утверждает наличие прямых рейсов/чартеров/мест/точного расписания как факт без проверенного источника.
- **Рабочие визы (ЮРИДИЧЕСКИЙ риск, «посадят»):** бот не предлагает и не перечисляет рабочие визы.

Механизм (2 слоя): промпт = первый слой; `validate_reply` = страховка после LLM (мутирует опасное); тесты = защита от регрессии и от ложных срабатываний.

## Ключевое требование — НЕ ловить ложные срабатывания
Валидатор должен глушить ТОЛЬКО уверенные утверждения. НЕ трогать отрицания/хеджи:
- «прямых рейсов нет», «скорее всего с пересадкой», «обычно ближе к осени», «нужно уточнить актуальность» — НЕ менять.
- «рабочими визами не занимаемся», «к сожалению, рабочие визы не делаем» — НЕ менять.
Реализовать **пофразно** (split по границам предложений): для каждого предложения условие = `AFFIRM.search(sent) and not NEG.search(sent)`. Так надёжнее одного мега-регэкспа. Прецедент анти-ложного в коде уже есть — `_GUARANTEE` с `(?<!не )` (`validator.py:36`).

## TASK 3 — `validate_reply` бэкстоп (`app/agent/validator.py`) — МУТИРУЮЩИЙ, пофразно
Добавить константы безопасных ответов:
- `SAFE_FLIGHT_REPLY = "По прямым рейсам и наличию мест лучше проверить актуальность по конкретным датам — уточним и подскажем точный вариант."`
- `SAFE_WORKVISA_REPLY = "К сожалению, рабочими визами мы не занимаемся. Можем подсказать по туристическим, гостевым и деловым визам по направлениям, с которыми работаем."`

Логика (в `validate_reply`, после существующих правок; текст уже `clean`):
1. Разбить `clean` на предложения (по `[.!?\n]+`, сохранив осмысленную склейку).
2. **Рейсы — только `funnel == "tours"`:** для каждого предложения, если `AFFIRM_FLIGHT.search(s)` И НЕ `NEG_FLIGHT.search(s)` — пометить как нарушающее.
   - `AFFIRM_FLIGHT` (утвердительное наличие прямых/чартеров): например matches — «есть прям…», «летают прям…», «прям… рейс/вылет/перелёт… есть», «чартер… есть», «есть чартер…», «выполняются прям…», «доступны прям…».
   - `NEG_FLIGHT` (отрицание/хедж — НЕ глушить): «нет», «не », «без », «пересадк», «уточн», «провер», «актуальн», «скорее всего», «возможно», «обычно», «ближе к осени», «под вопросом».
3. **Рабочие визы — только `funnel == "visa"`:** для каждого предложения, если содержит `рабоч\w*\s+виз` И НЕ отрицание `не\s|не занимаемся|не делаем|не оформляем|к сожалению|нельзя` — пометить как нарушающее.
4. Заменить нарушающие предложения на соответствующий SAFE-текст. Если нарушающих несколько — не дублировать SAFE-текст (склеить в один). Остальные (корректные) предложения СОХРАНИТЬ.
5. Добавить в `violations` маркеры: `"direct_flight_claim_blocked"` и/или `"work_visa_offer_blocked"` при срабатывании (для наблюдаемости на /admin/system через `observ.note_validation`).
6. НЕ ломать существующее поведение (markdown, tours_price_disclaimer, лог-сигналы guarantee/tickets-price/too_long/multiple_questions).
