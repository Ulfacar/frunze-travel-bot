# E5-02B-SOURCE — черновик правил из PDF v1.1

07.10.2026, Codex по просьбе Алана продолжить работу Claude. Подготовлены **208 записей**
в формате E5-02A. Это локальные исходные данные для дальнейшего review/import; БД,
публикация и диалог бота этим этапом не реализованы.

Пакет: `knowledge/kg_entry/draft-v1.1/{meta,countries,units}.yaml`.
Файлы записаны в синтаксисе JSON, который допустим в YAML; inline-комментариев в них нет.
Полный отчёт: `knowledge/kg_entry/draft-v1.1.audit.json`.

## Что сверено

Исходник — `Kyrgyzstan-visa-knowledge-base-v1.1.pdf`, 94 страницы, SHA-256
`141b9e1e570c916aab65f3dc40e927cc61ef182e1d155b997a5123091e36cca2`.
PyMuPDF читает PDF непосредственно, независимо от способа прежней конверсии E5-01.
Проверены клетки пяти таблиц против Markdown: 9 строк 2.10, 11 строк 12.6,
10 строк 13.1, 22 строки 13.2, 12 строк 4.1. Все 13 шаблонов А сверены по тексту.
Допускается только разница пробелов/оформления Markdown и зарегистрированные пометки SRC-03.

Блок Б.5 повторно разобран из PDF с сохранением отступа при переходе 88 → 89 страницы.
В сравнении с E5-01 разрешены только документированные исправления SRC-04/05 и склейка
PDF-переноса комментария. Любое иное изменение таблицы, шаблона или Б.5 останавливает сборку.
Визуально проверены PDF-страницы 24, 25, 59, 61, 62 (табличные исключения и контекст сроков).

Это сверка выбранных входов генератора, не всех 94 страниц и не юридическая актуализация.
Официальные сайты и вступление актов в силу в этом этапе не проверялись.

**126 записей имеют типизированное value; 82 сохраняют исходник без вычисляемого value.**
Статусы: 183 `needs_verification`, 22 `decision_pending`, 3 `blocked`, **0 `confirmed`**.
Это намеренно: утверждение в исходном PDF не подменяет approval новой версии базы.
`owner=unassigned:DEC-07`, `verified_at/by`, `review_due_at`, даты действия не выдуманы.

Каждая единица содержит полный исходный текст/строку/объект в `blocked_value.source`.
Это поле используется и для доказательств непроверенных значений; при будущем одобрении
нельзя просто переключить status — текущий preflight отклонит confirmed с blocked_value.
`source_text` — удобная копия, если укладывается в предел схемы; длинные строки полностью
сохранены в blocked_value. В audit есть selector исходника и страницы для всех 208 ID.

## Особые случаи

- Молдова: `KG.REG.EXEMPT.MDA` blocked, `value=null`, обе версии источника сохранены.
  MDA не попадает в DEFAULT.not_in_list, чтобы не обойти блокировку через общий путь.
  `KG.REG.TERM.MDA` — отдельный **срок оформления**, не освобождение.
- Греция/Чили: отдельные записи с числами 90/60, полученными из 2.10, а не общего
  `registration_exempt_days: 30` приложения Б.5.
- SW1/SW2/рабочая РК: `decision_pending`, `value=null`, SRC-03 и конфликтующие страницы
  13/15/82 сохранены вместе со ссылками на 9/59. Другие предложения 12.6 также не утверждены.
- TS/B/ЕР: числа из авторского абзаца 12.6 сохранены как typed value с
  `approval_in_source=true`; `confirmation_status=needs_verification`.
- Мальдивы/Малайзия/Куба/КНДР: в исходнике нет полного tuple days/window/work-permit.
  Не подставляется окно «30» по одному числу дней. У GCC отсутствует work-permit поле Б.5.
- Особые режимы и условная виза для резидентов GCC: допусловия, срок и страна выдачи
  документа должны быть выражены явно; набор стран сам по себе не делает правило полным.
- 13.1/13.2: варианты 1/3 рабочих дня, 30/60 дней доработки, «не позднее последнего дня»,
  календарные месяцы, старт отсчёта и перенос выходного не заменены одной удобной цифрой.
  Строки доступны полностью под устойчивыми смысловыми ID `KG.PT.*`/`KG.DL.*`.
- А.8/SRC-08 и А.11/SRC-07 заблокированы; остальные 11 исходных шаблонов тоже не подключены
  к отправке и требуют адаптации E5-04 под результат конкретного расчёта.

## Справочник и воспроизводимость

`source_v1_1/iso3166.json` — снимок 249 ISO3-кодов из pycountry 24.6.1.
`aliases.json` содержит 116 имён/сокращений, сопоставленных со справочником.
Корея в 2.10 → KOR (КНДР отдельно PRK); Македония → MKD, как Северная Македония в Б.5.
Это сопоставление названий, не признание права на безвизовый въезд.
Гражданство вне описанных групп не теряется из справочника анкеты.

`source_v1_1/capture.json` хранит выбранные PDF-страницы/таблицы.
`source-lock.json` фиксирует их хеши, инструменты и время подготовки. Снимок производный:
checksum доказывает неизменность, а проверка против PDF выполняется отдельно с `--pdf`.
Временные скриншоты лежат в игнорируемом `runs/e5-02b-source-audit/`.

```powershell
# Для проверки сохранённого снимка достаточно обычных requirements.txt
python scripts/build_kg_entry_bundle.py --check

# Для прямой сверки PDF нужны только dev-инструменты из этого файла
pip install -r requirements-knowledge-tools.txt
python scripts/build_kg_entry_bundle.py --pdf "C:\Users\alanb\OneDrive\Рабочий стол\Kyrgyzstan-visa-knowledge-base-v1.1.pdf" --check
python scripts/validate_kg_entry.py bundle knowledge/kg_entry/draft-v1.1 --source "C:\Users\alanb\OneDrive\Рабочий стол\Kyrgyzstan-visa-knowledge-base-v1.1.pdf"

# Новый каталог: сборка после проверки всех входов, без перезаписи пользовательских файлов
python scripts/build_kg_entry_bundle.py --output runs/kg-entry-review-copy
python -m pytest tests/test_kg_entry_source_bundle.py tests/test_kg_entry_validation.py -q
```

Успех — JSON `ok=true`, `imported=false`, `publication_approved=false` и exit 0.
`--check` ничего не создаёт/меняет. Генерация в существующие одинаковые файлы идемпотентна;
различающиеся файлы/посторонние записи отклоняются до записи. После сбоя файловой системы
может остаться частичный каталог: повтор дополняет отсутствующие файлы, если существующие
побайтно совпадают. Источник с другим SHA-256 требует нового mapping и review, не обхода проверки.

`bf9faa537ae600c433a064ab21b8d5969aa63ba99fc39ead224dc6fa5256dea5`.

идемпотентностью, сохранением активной версии при отказе, SQLite/PG-проверками. Alembic head
проверить по реальному дереву; старый `e5_knowledge_0008` из проекта уже не подходит.

подключение к боту, госпошлины 12.1–12.5 и остальное покрытие PDF остаются отдельной работой.

`needs_verification` нельзя массово поменять на confirmed ради «готового» импорта.
