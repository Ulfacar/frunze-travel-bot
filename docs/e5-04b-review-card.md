# E5-04B — карточка проверки въезда из CRM

09.10.2026. CRITICAL / solo / **PARTIALLY_READY**: локальная реализация проверена,
независимые reviewer/final auditor и PostgreSQL runtime UNKNOWN.

## Путь пользователя

В сохранённой анкете E5-04A появилась ссылка «Карточка для проверки»:
`/admin/case/{case_id}/kg-entry/review/{qualification_id}`. Карточка показывает:

- выбранную версию ответов, дату её проверки, причины обращения к специалисту;
- следующие вопросы RU/EN, неизвестные и неуточнённые ответы;
- сохранённые дополнительные сведения: документы на проживание, иностранные визы,
  туристическую группу, запрошенный тип визы и проверку длительности;
- недостающие сведения полной карточки по §3.4 / Б.4 исходного PDF;
- нерешённые проверки правил, истории и сроков, страницы/разделы исходных правил.

«Нет», «Клиент не знает», «Не спрашивали» и «Не применимо» различаются. Пустой список
документов не считается подтверждением отсутствия документов: рядом видна полнота списка.
При смене цели/добавлении версии старая ссылка сохраняет старые ответы и показывает
ссылку на новую карточку. Отчёт не пересчитывается новым алгоритмом при просмотре.
Название услуги и её ответственный читаются из текущей CRM; это явно обозначено.

Кнопка «Печать / сохранить PDF» открывает штатную печать браузера. Без JavaScript
доступна печать через меню браузера. Печатный стиль убирает навигацию, сохраняет версию,
ограничения и источники. В Chromium получен и просмотрен двухстраничный пример на
синтетических данных: `runs/e5-04b-crm-browser/review-demo.pdf` (ignored, не клиентские данные).
Длина печати зависит от анкеты и количества правил/дополнительных документов.

## Границы

Это **подготовка материалов**, а не выполненная передача менеджеру. GET ничего не
записывает: не создаёт задачу, назначение, уведомление или событие handoff. Связь услуги
и версии проверяется по контакту при чтении; отдельной сохранённой связи Application
или записи передачи нет. Анкета всё ещё общая для контакта. Старые выездные продукты
не превращаются во въездные от открытия карточки. Applicant/Application и E6-01 впереди.

Полная карточка Б.4 требует ещё сведений об участниках, приглашении, деталях цели,
кратности въезда и проверенного решения специалиста. Наличие всех полей partial profile
не объявляется завершённой квалификацией. Стоимость, точный срок, выбранный режим и
уверенность бота не выдумываются. Новые триггеры эскалации этим представлением не вычисляются.

Права прежние: только named full-admin, `ADMIN_KG_ENTRY_ENABLED` default OFF и
существующий `ADMIN_WORKDAY_ENABLED`. `SERVICE_CASES_ENABLED=false` запрещает запись
анкеты, но не чтение карточки. Расширение доступа ожидает ответа на вопрос владельцу;
отсутствие ответа не считается согласованием. Production не менялся.

## Защита и проверки

Domain API `read_qualification_card` проверяет actor и bounded ids до доступа к БД,
затем visa case/contact и конкретную qualification через прежнюю проверку целостности.
Другой контакт, направление и отсутствующий id не подменяются последней анкетой.
Повреждение снимка/источника или недоступность БД дают 503 без частично успешной карточки.
Значения из query string не являются ответами клиента. Jinja экранирует значения;
результаты имеют `Cache-Control: no-store` и `Referrer-Policy: no-referrer`.
Логи содержат только фиксированный текст, без payload и текста исключений.

Проверки: HTTP/domain негативные сценарии, контроль отсутствия SQL-записей, история,
ошибки источников, существующие анкета/workday/storage, Chromium mobile390/desktop1365
с/без JS, печать, фокус и overflow. Команды/результаты — task и handoff E5-04B.
Полный suite и deployment traps повторно не запускались: изменения ограничены чтением
и представлением, общая схема/запись/настройки не менялись. Старый date-test failure и
traps baseline остаются известными, не переклассифицированы в PASS.
