база знаний `Kyrgyzstan-visa-knowledge-base-v1.1.pdf` (94 стр., правила на 02.10.2026)

> Статусы сверены с кодом на коммите 779ed81; доказательство — в колонке/строке «Где».

**Модуль** здесь — единица, которую можно сделать, проверить и выкатить отдельно: свой
выход, свой флаг с дефолтом OFF, свои тесты, свои критерии приёмки. Это не замена 35
задачам ТЗ: колонка «Задачи ТЗ» показывает соответствие.

Статусы: `DONE` — есть модель/сервис, экран или маршрут и тесты в объёме строки (включение на проде не утверждается), `MISSING` — не начато, `PARTIAL` — код есть, доказательств неполно, `BLOCKED` —
ждёт внешнего, `UNKNOWN` — факт не замерен. Классы риска S / M / B / C — по `docs/protocol.md`.

## Правила для всех модулей

1. Границы диффа объявляются до начала и сверяются `git diff --stat` после.
2. Флаг с дефолтом OFF на всё, что меняет поведение для клиента или вид для менеджера;
   флаги новых модулей отделены от флагов редизайна и инбокса.
3. `python -m pytest tests -q`, затем `python scripts/prod_traps_check.py --diff-base <база>`.
4. Класс C — деньги, права, миграции, прод-данные, детекторы с порогами — требует
   независимого ревью (`codex-reviewer`) и финального аудита. Самоподтверждение
   исполнителя не принимается.
5. Деплой только по прямому слову Алана; после деплоя обязательна функциональная проверка
   в боевом контейнере. `/health` и «деплой прошёл» доказательством не считаются.
6. Приёмка — по указанным AC из [приёмки и демонстрации](crm-delivery/acceptance-and-demo.md);
   сейчас все 40 в статусе НЕ ПРОВЕРЕНО. Менеджер направления проходит свой сценарий сам.
7. Бизнес-политика DEC-01–12 разработчиком не придумывается: модуль делается на синтетике
   с выключенной функцией, пока решение не принято.
