## Как использовать

1. Алан читает ТЗ и фиксирует состав первого выпуска. Предлагаемый порядок — CRM после договора → пилот/переход → въездные услуги → дополнительные функции. В записи о выпуске указываются включаемые продукты, подтверждённые решения и результаты приёмки.
2. Сотрудники заполняют только пробелы своих продуктов. Известные этапы уже выписаны из встречи. Персональные документы и реальные переписки в эти файлы не вставлять; примеры обезличивать.
3. Владельцы закрывают решения в таблице. У каждого решения есть затронутая функция: нерешённая цена одной услуги не блокирует весь интерфейс или разработку на синтетике.
4. Разработчик начинает с E0, уточняет состояние данных, макет карточки и зависимости Bitrix. Задача берётся после проверки её предпосылок; статус «готово» подкрепляется ссылкой на результат.
5. Проверяющий проходит сценарии соответствующего выпуска. Все 40 AC изначально НЕ ПРОВЕРЕНО. Демонстрация на встрече и техническая проверка — разные записи.

Предлагаемые даты и трудозатраты находятся в разделе 18 ТЗ. План задач не добавляет к ним скрыто новые «обязательные» wow-функции. E7 — отдельный последующий выбор. Ответственный за задачу пока указывается ролью; человек назначается Аланом, это не поручение сотруднику от имени заказчика.

## Управление версиями

Markdown — источник требований. `backlog.json` хранит те же задачи в структурированном виде; `backlog.md` и лист «Задачи» собраны из него. Поля результатов в Excel изначально пусты. После начала ведения таблицы не пересобирать её поверх рабочих ответов: сохранить версию, перенести решения в Markdown с датой/автором, затем выпустить новую копию.

Word и Excel — копии на дату сборки. Изменение политики фиксируется текстом, автором, датой и перечнем затронутых требований; молчание, отметка «обсуждали» или готовый макет не означают утверждение. Новый исходник базы знаний не включается автоматически в бота.

Локальный комплект не изменяет приложение, сервер, тарифы и маршруты сообщений. Отправка опросов сотрудникам остаётся действием Алана; тексты подготовлены, сообщения никому не отправлены.
