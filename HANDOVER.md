## 1. Что строим

AI-агент-продавец для **Frunze Travel / GetVisa**. Встречает клиента в WhatsApp,
квалифицирует (задаёт вопросы), подбирает туры через **TourVisor** или оценивает визовый
кейс, и **доводит клиента до офиса/менеджера**. Менеджеры работают в собственной
админ-панели; сделки зеркалятся в **Bitrix24**.

Три воронки: **Туры**, **Визы**, **Билеты**. Цель ИИ — продавать и приводить в офис,
снимая рутину первичного контакта.

## 2. Архитектура и поток данных

```
                     WhatsApp (клиенты) ──── Wappi ────┐
                                                       ▼
TourVisor ──(поиск туров)──►  НАШ БЭКЕНД (бот + админ-панель, общая база Postgres/Redis)
                                │  ИИ-диалог: OpenRouter (Claude)
                                │  менеджеры работают в админ-панели
                                └──(создание/движение сделок, push)──►  Bitrix24 (CRM-зеркало)
```

Три важных уточнения:
1. **«Бот» и «админ-панель» — это ОДНО приложение** (наш бэкенд, одна база), а не два звена.
   Панель — окно в ту же базу, где живёт бот.
2. **Связи односторонние:** TourVisor отдаёт боту туры; бэкенд **пушит** сделки в Bitrix.
3. **TourVisor с Bitrix напрямую НЕ связан** — только через наш бэкенд (частый антипаттерн).

## 3. Потоки воронок (актуально)

**Туры:** приветствие → сбор (город вылета Бишкек/Алматы → даты → состав → бюджет →
звёздность/питание) → `search_tours` (TourVisor) → в офис / к менеджеру на дожим.

**Визы:** приветствие → опросник (имя → страна → возраст → семья → работа → прошлые поездки →
отказы → даты) → **внутренняя** оценка тона (клиенту проценты НЕ показываем, цен не называем) →
ведём в офис/онлайн-консультацию.

**Билеты:** полноценная воронка — маршрут → даты туда/обратно → пассажиры → прямой/пересадка →
передача менеджеру.

**Стадии канбана:** Новый → Квалификация → Подбор/оценка → В офис → У менеджера → Повторное касание.
**Передача менеджеру:** бот шлёт прощальную реплику и **сам глушится** (перехват — в нашей
панели, НЕ нативно в Bitrix).

## 4. Решения по реализации (факт)

| Тема | Решение |
|------|---------|
| Стек | Python 3.12 — FastAPI, OpenRouter (Claude, tool-use), httpx, Postgres 16, Redis 7, Jinja2+HTMX |
| Канал | **WhatsApp через Wappi** (живой). Telegram — опц. демо. Bitrix Open Lines — опц. |
| ИИ | **OpenRouter**: `anthropic/claude-sonnet-4.6` (осн.) + `anthropic/claude-haiku-4.5` (деш.) |
| CRM | Собственный **Postgres** + админ-панель. **Bitrix24 — зеркало сделок** (фаза 2, ждёт доступов) |
| Архитектура | Гексагональная (ports & adapters): каналы/CRM подключаются без переписывания ядра |
| Воронка | State-machine стадий + LLM ведёт диалог и вызывает инструменты |
| Ключ диалога | `<bot_id>:<номер>` — один номер у разных ботов = разные диалоги |

**Инструменты AI:** `ask_qualification`, `search_tours`, `score_visa`, `escalate_to_office`,
`handoff_to_manager`, `crm_update_stage`.

## 5. Админ-панель

«Предложить ответ» (ИИ), отметка исхода, раздел **Аналитика** («ИИ vs менеджер»).
