## Confirmed finding and correction

**F1 — P2 / baseline FIX_REQUIRED: an integral JSON float bypassed qualification group/family semantics.**

Trigger: a valid v2 request with `profile.applicants_count=6.0`. JSON Schema treats an integral JSON number as an integer, but baseline `app/knowledge/intake.py:28` and `:84` checked `type(count) is int` before enforcing family counts and the large-group stop. Consequently `6` produced `large_group_review`, while `6.0` produced no such stop. With `applicants_count=1.0` plus one child, `family_exceeds_applicants` was also bypassed.

This was not only a pure-function discrepancy: own synthetic SQLite probes called `save_qualification`, then reloaded the persisted revision. Both incorrect results survived storage. The original probe run was **2 FAIL / 6 PASS**; evidence is `own-sqlite.txt` and `source/tests/test_source_profile_independent.py`. This affects the authorized programmatic intake path; the native HTML integer parser already constructs an integer. The result still remained universally draft/review-only, and no approved legal route or client quoting permission was granted. It is therefore P2 rather than an authorization or legal-publication bypass.

Correction: both guards accept the already-schema-validated `int` or integral `float` consistently. The public request schema remains unchanged: fractional, boolean, zero, negative and string counts still fail validation. This does not normalize or rewrite saved input.

**Closure: PASS.** Both original persistence repros now pass on SQLite and real PostgreSQL. The numeric regression tests also verify that `6` and `6.0` suppress further questions via the same stop, and that `1`/`1.0` cannot omit the applicant when family members are present.

**Historical compatibility: PASS, with the established explicit replay boundary.** The storage fingerprint includes `intake.py`; changing it intentionally makes old exact replay return `qualification_replay_runtime_changed` / `profile_replay_runtime_changed`. Ordinary reads and exact retries do not recompute the historical result. Own probes seeded real immutable records with the actual archived 87ad intake function and the original runtime fingerprint captured before the fix, then restored the corrected runtime. They verified unchanged old read/result/hash, the original retry receipt, explicit replay refusal, a new corrected revision, and unchanged historical output. Contact and individual profile paths passed on SQLite; contact storage also passed on PostgreSQL. The probe harness does not alter any stored row after creation. No retained v2 evaluator or silent backfill is needed for this documented read/replay contract.

**F2 — P2 / r1 FIX_REQUIRED, closed on r2: saved integral numbers could not roundtrip through the native form.** Discovered independently by the separate final auditor after the initial r1 review. `values_from_request` rendered a schema-valid integer represented as a float using `str(value)`, e.g. `6.0` or `8.0`. `request_from_values` correctly accepts integer digit strings only, so an unchanged resubmission returned HTTP422. The auditor reproduced this through actual save → signed native GET → POST. This reviewer independently reproduced the bad native GET values for count `6.0`, child age `0.0` and child age `2147483647.0` on r1: **3 FAIL**, `native-numeric-r1.txt`.

**F2 closure: PASS on r2.** `values_from_request` displays an integer field's integral float as `str(int(value))`. This only changes form presentation. The strict POST parser, domain input, historical snapshot and hashing are unchanged. Own connected tests cover all three values through both contact and individual native routes: correct GET digits, successful unchanged POST, correct new revision, exact POST retry without another revision, original stored result/hash unchanged, then deliberately tampered decimal-string POST still rejected with422 and no write. Both historical runtime probes passed again. No PostgreSQL repeat was needed for this display-only change; actual storage/runtime files remain hash-identical to the r1 PG-tested versions.
