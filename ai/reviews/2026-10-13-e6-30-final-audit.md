## Confirmed audit findings and corrections

1. **Impossible retained signature revision accepted (R6).** After a normal
   signature and successful exact retry, controlled SQL replaced the retained
   result revision and matching top-level event revision with999 and recomputed
   the operation checksum. The original command still expected revision1, while
   the actual signed case was revision2. Retry returned success with the impossible
   receipt. R8 now requires result revision to equal expected revision plus one.
   Original independent FAIL is retained; unchanged corrective probe PASS.
2. **Malformed retained owner accepted (R6).** Replacing result.owner_login with
   a JSON object and recomputing its checksum likewise returned successful retry.
   R8 now requires a bounded, normalized nonempty string. This agrees with the
   reviewer's independently found null-owner variant; neither was a demonstrated
   permission expansion. Current owner is deliberately not substituted for the
   original historical owner after legitimate reassignment. Original FAIL and
   corrective PASS are retained.
3. **Accepted noncanonical actor creates an unusable opening (R8; corrected R11).**
   `Actor('ADMIN', True)` is accepted and command.actor becomes `admin`, but the
   old `open_case` helper receives the original actor and writes event.actor as
   `ADMIN`. The committed opening then fails its own immediate exact retry with
   `preliminary opening event mismatch`; signing is also blocked. Native actor
   construction already normalizes, so this is a domain API consistency defect.
   R11 explicitly rejects noncanonical identity before any operation write. Own
   uppercase/mixed-case/space variants now refuse opening and signing without
   mutation; a subsequent canonical opening/signature/exact retry succeeds and
   creates one task. This changes only the new API boundary; old contract actor
   semantics remain byte-identical. Original FAIL remains visible.
