## Independent finding A1 — HIGH, actual destination can change after admission

In r1 `app/core/orchestrator.py:583`, `_reply` admits the current adapter descriptor and `msg.chat_id`, then invokes `_deliver_reply`. That function awaits `panel.add_message` before `adapter.send(msg.chat_id, text)`. Both the adapter and `Message` are mutable. The guard's descriptor comparison happens before this preparatory await. Mutation of the recipient, actual Wappi profile, or provider origin during that wait can therefore send to a different already stopped route while holding admission for the earlier unbound route. The installed method returns `True` and performs successful-send effects.

Own reproducible negative checks:

1. `python -X utf8 -m pytest auditor_channel_probes.py -q --tb=short --basetemp=auditor-pending-r1-tmp --junitxml=runs/auditor-pending-r1.xml` in the own r1 copy: **2 FAIL / 10.45 s**. Recipient/profile mutation during the awaited pending log, counted fake provider.
2. Stronger unchanged-source proof using the actual `WappiAdapter.send` and an injected fake HTTP client: `python -X utf8 -m pytest auditor_channel_http_probes.py -q --tb=short --basetemp=auditor-http-r1-tmp --junitxml=runs/auditor-http-r1.xml`: **3 FAIL / 8.99 s**. Recipient/profile/origin cases capture the actual HTTP URL, profile parameter and recipient. Each request targets the already stopped route instead of the admitted one. No external HTTP request is made.

The second probe is the authoritative route proof for the replacement snapshot: instance-bound mock closures from the first probe do not establish the actual destination of a captured adapter copy. Required fix: retain the admitted exact adapter/recipient through all preparatory awaits, or reject a changed descriptor immediately at actual provider invocation. Do not re-admit by falling back or retrying a provider callback.
