## Smallest safe implementation boundary

The E6-04 finding establishes a real pattern: Python container equality can accept JSON `false` versus `0`, or integer `1` versus float `1.0`, after the ordinary stored checksum is recomputed. It does not establish that every equality in these seven modules is defective. Existing input schemas, `type(...) is int`, `is True`/`is False`, hashes of reconstructed commands, and scoped foreign keys may already reject a proposed substitution.

Use the existing `app.knowledge.review.canonical` or `_hash` comparison at a demonstrated JSON integrity/replay boundary. Canonical comparison already preserves dictionary key-order independence, list order and exact JSON representation, and rejects non-finite numbers (`allow_nan=False`). No new dependency, general-purpose validation framework, global equality override, schema rewrite, or payload-version migration is necessary.

Patch only a boundary with a preserved baseline reproduction and a corrective rejection check. If the original service already rejects the adversarial receipt, record that result and leave the comparison alone unless a different meaningful probe establishes the gap. Runtime-only dictionaries currently contain strings/nested string metadata and do not automatically need speculative changes merely because they use Python equality.

Keep SQL identifiers, trusted actors, approved source mappings, legal facts, reductions, dates, scope, limits, lock ordering, request-key allocation and snapshot layouts unchanged. Do not normalize old values, recompute old receipts, update stored hashes, reinterpret numeric legal values, or seed policy authority to make a test pass.

## Compatibility conditions that can otherwise invalidate the fix

1. **Do not equate all integral floats with corruption.** `entry_deadline_sources.RECALCULATE` uses JSON Schema integer fields, and `validation.schema_errors` uses `Draft202012Validator`. The installed checker (`jsonschema/_types.py:195–204`) explicitly accepts integral floats for integer schema values. `check_tree` also permits finite floats. Some paths subsequently use strict `_id`; others retain the supplied representation. This is source-confirmed behavior, not proof that every such value completes a write. Before replacing scalar SQL-column/JSON comparisons or tightening normalizers, run a positive baseline writer/read/retry control with the accepted representation. Preserve legitimate writer-produced receipts. Prefer comparing an immutable JSON snapshot with the corresponding deterministic reconstruction, rather than silently redefining all accepted numeric input.

2. **Runtime fingerprint changes propagate.** `qualification_storage._runtime()` hashes its own file and is used by `applicant_profiles._runtime()`. Editing qualification storage therefore changes per-applicant qualification runtime identity even if the E6-17 source file remains unchanged. Recheck both contact and applicant old read/exact retry plus explicit replay refusal. Deadline `_runtime()` also hashes its storage/source code: old ordinary deadline reads and retries must survive, and explicit replay must refuse incompatible runtime rather than silently pass or rewrite history.

3. **Exact retry preserves the immutable receipt, not necessarily a stale live overlay.** Issued-document responses must still overlay current quarantine status. Process retries must still show current readiness/policy/invalidation. Deadline reads must still mark a superseded anchor unavailable operationally while keeping the historical snapshot unchanged. Do not "fix" a retry assertion by returning an obsolete favorable summary.

4. **Reducers and historical definitions remain pinned.** Documents, issued records, process histories and interviews already reconstruct state from their appropriate immutable sources. Canonical comparison must not switch to the active catalog, discard older reducer support, change an edge, materialize missing evidence or require an active current policy for reading valid historical receipts. Policy expiry/removal is not permission to resume collection, sending or procedural progression.

5. **Malformed history remains unavailable, not auto-repaired.** Reject before appending or mutating any dependent event. Bounded errors and existing unavailable UI responses should remain intact. No raw command/result contents or private connection material should be added to logs or reports.
