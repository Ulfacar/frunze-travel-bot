## Critical reuse and recovery pitfalls

- **P1 identity/authority:** case contact proves payer association, not applicant identity. A transport latch blocks the entire exact route; if one phone represents multiple people, do not claim per-person selective sending on that route. Never accept actor/owner/route/source approvals from message text or form hidden fields alone.
- **P1 transaction/order:** `bind_stop` takes route advisory lock, registry-capacity lock, then case/Dialog; `record_action` takes case. Calling public writers sequentially leaves a send window; nesting them can invert locks and own transactions. Compose within one transaction in existing order; no provider calls inside retryable writers. Sample policy day/time after waits.
- **P1 retained semantics:** `_registry:161` requires generic `action=='handoff'` when the observed phase was active/paused. Merely replacing it with `interrupt` invalidates old validation assumptions. Keep v1 reducers/cards/receipts byte- and behavior-compatible; separately version new cause/connection evidence or add an explicit retained validator. Do not rewrite `channel_suppression` in historic snapshots.
- **P1 uncertain delivery:** send-first may finish one already admitted callback before the writer acquires its lock; bind-first must block the callback. State this precise linearization contract, not impossible retraction. Timeout/cancellation/cleanup failure must never reinvoke the provider. Failure before commit must not claim a saved stop, manager ACK or delivered notification.
- **P1 consent and pending state:** stop collection after refusal/withdrawal even after ACK. Preserve the original card; a later correction cannot erase the reason or reopen automation. A new raw-message adapter must not route consent withdrawal into legacy silent fact extraction.
- **P2 capacity/recovery:** interview reserves terminal events, channel registry is bounded at128 stops/4MiB. New cause journal/registration needs explicit bounds and terminal reserve. At full capacity, do not report a stop that was rolled back or let the triggering turn fall through into advice; define the operational failure state and durable recovery. Existing unrelated unbound routes are currently admitted, so no global safety claim follows from a failed new binding.
- **P2 activation versus policy:** expired/removed binding policy does not resume saved latches; removing deployment activation currently bypasses this guard for that account. These are different controls. Preserve the present contract unless an explicit owner decision authorizes a change. Missing/corrupt DB on an activated route must fail closed, including a negative lookup.

### Minimum positive normal-turn contract

**Prefer a small typed answer adapter over greetings-only admission.** A greetings-only guard is safe only as a bounded interruption filter; sending every actual answer to a human does not establish a usable connected ordinary interview. Neither design may use “no interrupt found” as authorization to fall through into the generic visa/tour LLM.

1. Consume all inputs in the explicitly assigned KG scope before debounce, voice interpretation, silent legacy extraction, persona and FAQ. Even on an already stopped route, permit only the necessary internal consent/receipt processing; the existing send guard still suppresses autonomous output. Unknown policy/subject/state or processing failure is consumed with a controlled local error, never legacy fallthrough.
2. Obtain a trusted current prompt context: exact case/person/interview; phase and revision; catalog/source/policy hashes; language; the actual current displayed field or question batch and its provenance. Current drafts alone do not prove they were shown. A narrow raw-text path can support **one unambiguously identified displayed field**; a batch with multiple possible fields requires a structured answer identifying the pinned field or an explicit clarification. Never assign a bare `no`, date or number to the first field by position. Bind incoming provider identity/message ID to this context; client text cannot choose an actor or another field.
3. First detect human/consent/complaint/exception interruptions in the complete raw message. Then parse a supported normal answer by **whole-input** matching against the displayed field's existing catalog kind: exact enum label/code in its pinned RU/EN catalog; exact boolean aliases for one boolean field; strict ISO date for one date field. Supporting bounded catalog integers and explicit country codes is also small and avoids needless handoffs on ordinary group/age/citizenship questions. Reuse existing type/semantic validation, including ranges, future-date limits and conditional applicability. Do not infer a visa type, legal basis or eligibility from unstructured prose. Unknown/not-applicable must be explicit values only where the existing field permits them.
4. A positive consent answer is valid only through the existing consent fields/evidence flow. `okay`, a greeting, silence or merely continuing the conversation never grants consent. Possible refusal/withdrawal has precedence over every normal parser, including after ACK. No parser may preserve a personal-data correction when the collection block is active.
5. Under the correct locks and CAS, append the typed answer through the retained interview semantics, evaluate fresh stops, and atomically create/link the causal stop receipt if the answer triggers one. A successful ordinary answer returns only newly generated bounded typed questions/status for that same interview, at most3, with existing consent gating. A literal greeting/acknowledgement may leave facts unchanged and produce a neutral deterministic response or repeat the existing permitted prompt; it does not authorize generic advice. Pending/acked/blocked states produce no autonomous questions.
6. Final delivery must still pass the existing route guard. Pin the accepted input and returned draft revision; do not silently reapply an old answer to a changed prompt after CAS failure. Exact duplicate provider messages return the original receipt and do not append or send twice. A provider send with unknown outcome must not be blindly retried. The input key must distinguish separate identical utterances while detecting changed content under the same provider ID; hash kind/voice/attachment metadata as well as text where relevant.

Minimum positive tests: a consent-compliant ordinary enum→boolean→date sequence across saved/reloaded state; a known integer/country if supported; greeting with no fact mutation; wrong type, multiple displayed fields, stale prompt, mixed “yes, but…” interruption, duplicate ID, language/catalog drift, and a typed answer that atomically triggers a stop. This is a connected positive path; it is not a claim of unrestricted natural-language intake or the separate complete Appendix Б.8 goldens.
