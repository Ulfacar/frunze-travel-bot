## Findings from the existing implementation

1. **The renderer already has the right literal boundary.** `template_preview.preview` substitutes only catalog-declared typed slots and never reparses inserted braces/HTML/instructions. Missing fields stay visible; `unresolved_calculation` cannot be filled. All outputs set `publication_approved=False`, `send_allowed=False`. Preserve these semantics in the durable adapter; persistence is not a reason to evaluate source expressions or substitute an arbitrary template body.

2. **An active storage policy must not turn source text into approved facts.** All 13 catalog templates require verification; A08/A11 are blocked. Source A03 contains literal service pricing/legal deadlines; A07 says a visa/file is ready; A09 says a refusal occurred; A13 promises a manager response interval. A template with zero unresolved slots can still contain unsupported claims. Keep source status, unresolved list and the draft/no-send label on saved views and every printed output. A source-proof reference on the storage policy does not approve those claims.

3. **Quote terminal-state restrictions do not fit notification drafts.** `entry_quotes` blocks approved/refused/closed applications for new usable quotations. Appendix A includes approval and refusal drafts, and block 14 has corresponding terminal/outcome stages. Do not copy that gate into this journal. Permit a scoped historical draft on an existing terminal application under valid storage authority, while clearly distinguishing its manually entered content from verified application facts. No application transition follows from saving it.

4. **Historical rendering needs real version dispatch.** `TemplateCatalog` currently accepts one module-global `CATALOG_SHA256`; `preview` also emits that global constant. A future replacement of that constant would invalidate old catalogs or mislabel their output if reused naively. Retain named catalog/rendering versions with exact digests and immutable assets/snapshots; replay must select the recorded version rather than today's global loader.

5. **The source asset is missing from current image packaging.** Dockerfile copies process/document/interview catalogs but does not copy `knowledge/kg_entry/templates_v1_1/catalog.json`. A source-checkout-only implementation could pass locally while deployed-package reads/previews fail. Include retained template assets and verify the package boundary in this slice; do not claim an image build was run unless actually run.

6. **The existing native preview intentionally has no persistence gates.** `kg_templates` calls the existing KG/workday/read gate and its tests assert no SQL and no write permission requirement. Add a separate application-scoped save flow with existing write/CSRF/full-admin gates; do not silently turn the old read-only preview POST into a write or weaken its established tests.

7. **Existing OutboxJob is the wrong storage abstraction here.** It describes recipient/account-scoped outgoing send intents with delivery/attempt state (`models.py:256`). A draft without a recipient is not such an intent. A separate immutable table avoids inventing destinations, pending-delivery status or future worker permissions.

## Minimal complete design and required corrections

### Authority, scope and meaning

- Server storage policy is absent/empty by default. Validate explicit current existing full-admin operators, validity window, permitted template IDs, exact catalog digest and bounded source/privacy authority references. Policy parsing failure disables new writes; it never promotes source text. Fixtures remain explicitly synthetic. This policy grants storage only.
- Current full-admin identity and exact case/application scope are checked before access, including retry. Derive applicant from the existing application and use composite scope FKs. A payer/contact is not the applicant. Do not attach a quote, passport, profile or consent merely because it belongs to the same contact.
- Pin application identity plus exact observed event ID/revision/hash at preview/save. Later application changes mark the draft context changed; old history replays from its pinned event, not the latest state. Do not reconstruct observed history by a timestamp prefix that later rows can alter.
- If fields are manually typed, record/label that provenance. Binding a draft to an application does not verify the entered passport number, refusal cause, price, date or deadline. The smallest slice does not auto-fill or assert business truth from other services. Any later autofill would require exact source pins and its own current-validity checks.
- Preserve literal source branches and RU/EN sections as the current catalog provides them. Do not imply that storing the combined source template selects a language or validates conditional applicability. Unknown placeholders and blocked calculation expressions remain literal, visible gaps. Empty/missing typed input has a defined meaning and must not become a fabricated value.
- PII-bearing slots require the stated storage/privacy authority; full-admin rights alone are not consent. No actual privacy/retention decision is supplied here. Keep live policy empty and real data out of fixtures/reports. No new destination, attachment, URL fetch, arbitrary body or disclosure mechanism belongs in this slice.

### Preview, save and idempotency

- Preview is read-only. It returns typed normalized values, application pin, policy/catalog/render version and exact rendered result/hash. The save envelope signs actor/session, operation, target, expected revision, request key, complete typed values and all version/result pins. Server save recomputes under the existing case → application lock and rejects a changed preview.
- Obtain the actual server timestamp and recheck policy/day after waiting for locks. Do not store a row whose timestamp falls outside the policy merely because the request began earlier. Validate clock ordering against previous draft and pinned application event.
- Persist a single immutable receipt containing command, policy/authority snapshot, exact source/template/catalog pins, renderer version, typed values and result. All result flags remain draft/no-publication/no-send. Later changes append; they do not update an earlier body or decision.
- Resolve an authorized exact retry before current-policy expiry/removal, CAS, fresh preview checks or new-write capacity checks. Compare with the original recorded command/version, not today's policy. Return that original receipt; show current storage/source/context status separately. Same key with changed values/template/actor or target inside the chosen idempotency namespace fails.
- State the dedup namespace explicitly. The proposed per-application key is adequate for confirmation dedup: concurrent/double-submit/lost-ACK retries create one receipt. The form signature must prevent moving that confirmation to another application. Do not claim global content dedup or outbound delivery dedup; a new intentional command may create another draft with identical text.
- If the application journal contains different template IDs, its revision is a sequence of saved draft artifacts. Do not blindly call all earlier templates superseded merely because a different template was saved later. If replacement semantics are desired, declare an explicit same-draft lineage; that is not necessary for the minimal journal.

### Replay and bounded storage

- Reproduce every row from its retained catalog and renderer version. Validate contiguous revisions, predecessor, request hash, creator/authority, policy validity at recorded time, scope/application pin, template identity and exact canonical typed values/result. Compare canonical structures so booleans and integers do not pass through Python equality as equivalent.
- Fully rehashed wrong text, unresolved slots, source hashes, catalog/render version, scope or approval/send flags must fail semantic replay. Hashes alone do not establish outside authenticity against an attacker able to replace the entire database and trusted assets; the task correctly excludes that claim.
- Historical reads and exact retries must not depend on current catalog availability, current source approval or an active policy. Retain the required old assets/renderer and separate old-history rendering from new-form catalog loading. A current source mismatch disables new saves and produces a current warning; it does not invalidate an otherwise valid old receipt.
- Bound field count, per-value characters, UTF-8 bytes, JSON depth/nodes, row payload, journal bytes and revision count at the domain boundary as well as HTTP. Reject non-finite values and unexpected nested objects before canonicalization. Query only the selected application's bounded journal; fetch limit+1 and fail closed on overflow, never silently truncate validation.
- At capacity, old reads/retries remain available while new saves fail. No terminal reserve is required for this draft-only append journal because it introduces no delivery/acknowledgement state that would require a final event. Do not create an unimplemented deletion/retention/resume workflow.
- Add scoped FKs, unique revision/key constraints and existing ORM/bulk immutability guards. Confirm JSON/model types on PostgreSQL rather than relying only on SQLite. Preserve old preview behavior and unrelated money/application/interview/task/message tables.

### Native and failure behavior

- Keep the established full-admin/KG-OFF/workday/write/CSRF boundaries. Read-only preview and persistent save are visibly different actions. After preview, explicit confirmation saves only that exact version; no send/release/approve button exists.
- Strictly parse bounded URL-encoded forms with duplicate-key rejection and strict percent-decoded UTF-8 handling. Bound every security field, canonical numeric/boolean value and typed JSON envelope. Invalid Unicode, overlong/malformed encodings, extra/duplicate fields or surrogate/control input must return a controlled error without a row or a server error. Do not copy a parser with replacement decoding into this flow.
- Escape all rendered source and entered values in page/history/print. Do not turn an entered HTTPS placeholder into a fetched resource, attachment, HTML or an automatically followed link. Preserve the existing prohibition on credentials inside URLs and source-expression execution.
- Mark saved history, current policy/source availability and unresolved/source-blocked conditions independently. Do not use an ambiguous `ready`/`usable` flag that could mean approved for delivery. Print carries the draft/no-send warning and source/version context, including multi-page templates.
- Commit outcome unknown must preserve the original signed save fields and key even if the follow-up read also fails. Show retry without regenerating a request, dropping values or requiring a fresh active policy. Do not report failure as definitely rolled back if commit acknowledgement was lost.
