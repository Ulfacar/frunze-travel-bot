# Руководство по работе с протоколом

## Что читать

Агент начинает с `AGENTS.md`, `ai/protocol.json`, `ai/PROJECT.md` и `ai/STATE.md`.
Затем читает только материалы текущей задачи. Ядро определяет процесс, профиль — факты
проекта, состояние — точку продолжения. Старые отчёты не заменяют проверку кода.

```text
AGENTS.md                  правила для агента
CLAUDE.md                  ссылка на общее ядро и роли
ai/protocol.json           версия, режим, тип проекта
ai/PROJECT.md              подтверждённые факты текущего проекта
ai/STATE.md                активная задача и следующий шаг
ai/ROLES.md                контракты ролей
ai/PROMPTS.md              готовые запросы
ai/playbooks/              дополнительные проверки по типам проектов
ai/templates/              чистые шаблоны
ai/tasks/                  реальные задачи (создаются по необходимости)
ai/reviews/                реальные ревью
ai/handoffs/               передача контекста
ai/decisions/              важные решения
tools/ai_protocol.py       установка и проверка
```

Рабочие задачи/ревью/решения создаются по мере необходимости, а не заранее для каждой мелочи.
Не храните секреты, выгрузки клиентов и приватные логи в этих документах.

## Установка

Из папки комплекта (или установленного проекта):

```powershell
python tools/ai_protocol.py install "C:\Projects\Example" --name "Example" --profile bot --mode team
python tools/ai_protocol.py install "C:\Projects\Example" --name "Example" --profile bot --mode team --apply
python tools/ai_protocol.py check "C:\Projects\Example"
```

Python 3.10+, стандартная библиотека. Можно установить в папку без Git. Предпросмотр — по
умолчанию; записи только с `--apply`. Повтор с теми же параметрами пропускает идентичные файлы.
Установка переносит только явный список публичных файлов из `ai/protocol-manifest.json`.
Профиль и состояние создаются из чистых шаблонов: факты исходного проекта не переносятся.

Проверка комплекта перед распространением:

```powershell
python tools/ai_protocol.py bundle
python -m unittest discover -s tests -v
```

Тесты поставляются в исходном комплекте; в прикладные проекты не копируются.
`bundle` проверяет структуру публичного комплекта, не корректность содержимого и не доверие к нему.
Не запускайте установщик из непроверенного источника.

## Режимы

| Режим | Обычная разработка | Критические изменения |
|---|---|---|
| solo | Реализация, проверки, отдельный проход SELF_REVIEW | Независимое ревью и аудит обязательны |
| team | Независимое ревью человеком или отдельным контекстом агента | Независимое ревью и финальный аудит |
| strict | Независимое ревью и сопоставление требований с доказательствами | Отдельный аудитор и доказательства восстановления |

Режим задаётся при установке. Менять его нужно явно в рамках решения владельца проекта,
а не посреди задачи для обхода недостающего ревью. Имена моделей в универсальное ядро не зашиты.
Если независимый проверяющий недоступен, реализация и локальные проверки продолжаются;
итог — PARTIALLY_READY с конкретным незакрытым требованием, без выдуманного APPROVE.

## Existing projects

**Уже есть AGENTS.md, CLAUDE.md или ai/?** Сначала запустите предпросмотр.
Любой отличающийся файл из плана останавливает установку целиком; флага принудительной
перезаписи нет. Даже изменённый после первой установки профиль считается конфликтом.
Для повторной проверки используйте `check`, не повторную установку.

Для объединения:

1. Установите комплект в отдельную пустую папку, например `C:\Projects\protocol-preview`.
2. Сравните инструкции и сохраните все действующие ограничения проекта.
3. Добавьте нужные разделы ядра в существующий `AGENTS.md` или согласованную ссылку на них.
4. Объедините `CLAUDE.md`, не теряя старые импорты и инструкции.
5. Перенесите нужные файлы `ai/` и установщик, разрешая каждый конфликт отдельно.
6. Заполните профиль текущими фактами, проверьте diff и выполните `check`.

Если структура намеренно адаптирована, проверяйте её вручную: комплектный checker ожидает
перечисленные в манифесте пути. Он не проверяет, читает ли конкретный AI-клиент инструкции.
Установщик не заменяет текущие Git-настройки, CI и зависимости приложения.

## Что означает проверка

```powershell
python tools/ai_protocol.py check "C:\Projects\Example" --strict
```

Обычный `check`: конфигурация, обязательные файлы, наличие профиля и состояния.
`--strict`: дополнительно основные поля профиля и команды заполнены подтверждёнными значениями
или `N/A — причина`. Это проверка заполненности, не истинности фактов и не качества приложения.
Другие UNKNOWN проверяются в контексте задачи и риска.

Коды выхода: `0` — заявленная проверка пройдена, `1` — ошибка/конфликт, `2` — неверные аргументы CLI.
Предпросмотр не создаёт даже целевую папку. Ошибка записи откатывает созданные в этом запуске
файлы; непустые папки и чужие файлы сохраняются. При принудительном завершении процесса или
сбое питания могут остаться новые файлы: проверьте вывод/содержимое перед повтором.
Не меняйте целевые пути параллельно с установкой. Это локальный инструмент, не защита от
злоумышленника, одновременно подменяющего каталоги во время файловых операций.

## Новая сессия и завершение задачи

Для простой правки достаточно результата и подходящей проверки. Для существенной задачи
используйте `templates/TASK.md`, затем `templates/HANDOFF.md` и обновите `STATE.md`.
В монорепозитории опишите рабочие каталоги и команды по компонентам; при необходимости добавьте
профили в `ai/projects/` и scoped-инструкции внутри пакетов. Корневой профиль указывает на них.
В параллельных ветках ведите отдельные строки состояния; «самый свежий файл» может относиться
к другому направлению.

Деплой нужен только если входит в задачу. Рабочая локальная правка не обязана ждать выдуманного
продакшена, а успешный деплой сам по себе не доказывает выполнение бизнес-сценария.

## Обновление и удаление

Перед обновлением сохраните собственные изменения через используемую систему версий/резервную
копию. Новую версию сначала разверните отдельно, сравните и объедините правила, шаблоны и
манифест. Установщик не является автоматическим обновлятором. Не заменяйте накопленные
`PROJECT.md`, `STATE.md`, задачи, решения, ревью и handoff пустыми шаблонами.

Автоматического удаления нет: документы могут содержать полезную историю. При ручном удалении
ориентируйтесь на манифест и собственный diff, не удаляйте всю папку `ai/` вслепую.
