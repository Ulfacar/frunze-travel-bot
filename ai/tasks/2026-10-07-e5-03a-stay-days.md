## Goal and scope

CALC-02 требует проверки каждого дня скользящего окна по всем интервалам, без двойного
счёта пересечений. Пока вычислителя нет; KG.RULE.COUNT_ENTRY_DAY/COUNT_EXIT_DAY/WINDOW_ANCHOR
имеют decision_pending и NULL. PDF physical page 24 прочитана напрямую, SHA сверена;
архитектура требует утверждения эталонов до точного клиентского остатка.

Локальный pure review calculator + CLI: валидированный bundle, явно выбранный кандидат
visa_free_regime, отдельный snapshot актуальных интервалов и явная proposed policy.
Числа лимита только из typed value, не из blocked_value. Нет автоопределения режима,
данных клиента/паспортных номеров, записи истории/DB, обращения к slots, боту/LLM/ЕСУВМ.
Даты — календарные Asia/Bishkek, не часы и не рабочие дни. CALC-03/04 вне этого этапа.

## Acceptance

| ID | Scenario | Expected |
|---|---|---|
| AC1 | Duplicate/overlapping/out-of-order closed intervals | Объединение дней, порядок не влияет на арифметику; provenance IDs сохранены |
| AC2 | Each planned date / leap day / year boundary / window edges | Inclusive backward window exact length; сравнение с независимым brute-force oracle |
| AC3 | Explicit entry/exit policy, same-day trip | Нет скрытой включительности; day count по указанным параметрам |
| AC4 | Open current stay / planned continuation / new entry | Open history capped as_of без фиктивного выезда; continuation без второго въезда; conflicting new entry блокируется |
| AC5 | Incomplete/unconfirmed history, passport/basis change | Findings, no exact client remainder/eligibility; missing data не становится нулевой подтверждённой историей |
| AC6 | Missing policy, NULL rule, wrong country/kind, invalid dates/input | Отказ или needs_input; source evidence не превращается в value; нет private payload в ошибках |
| AC7 | Reproduction/CLI | Input+bundle+algorithm hashes/versions, deterministic; read-only, fixtures из synthetic dates; действительные правила не меняются |

## Risk pre-audit — builder, NOT independent

- Все результаты всегда review_only, may_quote=false, entry_eligibility_evaluated=false,
  exact_remaining_days=NULL. Даже confirmed входной флаг не даёт полномочий публикации.
- Proposed policy содержит оба boolean без defaults; WINDOW_ANCHOR только явно each-day backward inclusive.
  Отсутствие policy даёт no arithmetic. Это сценарии для утверждения, не утверждённые нормы.
- Будущий DB adapter должен читать актуальные stay_intervals и их revisions/IDs, не slots.
  Этот этап не меняет решения о ПДн/ретеншне и не реализует persistence этой истории.
- Дубли не суммируются; open end не считается exit; разные основания/паспорта не фильтруются
  молча. Математический сценарий считает присутствие, применимость к безвизу требует проверки.
- Headroom внутри одного окна не равно будущему разрешённому сроку. Не выдавать его как остаток.
- Ограничить интервалы/длину плана/окна, валидировать даты, underflow/overflow и ошибки Unicode/JSON.
- Recovery: pure read-only функции; production не меняется. Возврат локального кода не требует миграций.
