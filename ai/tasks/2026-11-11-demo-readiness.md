## 🔴 Дыра 1: учёток daulet и marsel нет вовсе

На проде семь логинов: `admin`, `ademi`, `medina`, `eliza`, `grisha`, `aisina`,
`grisha-admin`. Даулета и Марселя нет, хотя их скоупы ботов в коде заведены ещё
05.11 (`manager_scope.BOT_SCOPE_BY_MANAGER`) — то есть всё готово, кроме самих учёток.

Решается запуском на сервере:

    cd /root/frunze-travel
    python3 scripts/add_manager_accounts.py daulet:Даулет marsel:Марсель
    docker compose -f docker-compose.yml -f docker-compose.vps.yml --env-file prod.env up -d app

Скрипт добавляет только недостающих, существующие учётки не трогает, делает копию
`prod.env` и кладёт пароли в файл `new-logins-<дата>.json` рядом с правами 0600.
Рестарт обязателен: `MANAGERS` читается при старте.

**Запускает Алан.** Агент в `prod.env` не пишет: это файл с паролями всех менеджеров.

То есть вся часть «после договора» на демонстрации будет пустой: нажать «Договор
подписан → создать услугу» по шенгену не получится, механизм ответит «product has no

ответам Медины), но на боевую CRM не публиковался. Публикация — отдельное действие:

    python3 scripts/publish_kg_visa_funnel.py --funnel schengen --yes --dsn "<боевой DSN>"

Обратимость: версии процессов версионируются, новая публикация не ломает старые
заявки — а заявок сейчас и нет вовсе.

Открытыми остаются два вопроса Медине (собеседование по шенгену; подготовка одной
стадией). Публиковать до её ответа можно — следующая версия выпускается поверх.

## Воронки: что собрано и чем публиковать (11.11, вечер)

Собраны и лежат в образе три визовых процесса по ответам Медины. Опубликован пока
только шенген — остальные ждут запуска команды: публикация это запись в боевую базу,
и агенту она заблокирована как прод-действие.

| Воронка | Продукты | Состояние |
|---|---|---|
| шенген | `visa_schengen` | ОПУБЛИКОВАНА 11.11, версия #4, 19 этапов |
| шенген | `visa_italy` | не опубликована — Медина: «Италия относится к Шенгену» |
| США | `visa_usa` | не опубликована; в базе лежит старая версия из ТЗ (9 этапов) |
| общая | `visa_china`, `visa_korea`, `visa_japan` | не опубликованы, воронок у них нет вовсе |

Команды (в боевом контейнере, по одной):

    docker exec frunze-travel-app-1 python scripts/publish_kg_visa_funnel.py --funnel usa --yes
    docker exec frunze-travel-app-1 python scripts/publish_kg_visa_funnel.py --funnel schengen --product visa_italy --yes
    docker exec frunze-travel-app-1 python scripts/publish_kg_visa_funnel.py --funnel generic --product visa_china --yes
    docker exec frunze-travel-app-1 python scripts/publish_kg_visa_funnel.py --funnel generic --product visa_korea --yes
    docker exec frunze-travel-app-1 python scripts/publish_kg_visa_funnel.py --funnel generic --product visa_japan --yes

Без `--yes` та же команда — сухой прогон: печатает план и в базу не ходит. Публикация
выпускает НОВУЮ версию процесса; ранее заведённые заявки остаются на своей версии, а
заявок в базе сейчас нет вовсе.

**Про США отдельно.** Прежняя версия собиралась по ТЗ 01.10 без менеджера и расходится
с её словами не косметически: нет предоплаты, личного кабинета, консульского сбора и
выдачи паспорта; проверку анкеты делал клиент, а не менеджер; исключений нет ни одного,
то есть отказное дело некуда деть. Пока новая версия не опубликована, на проде живёт
старая.
