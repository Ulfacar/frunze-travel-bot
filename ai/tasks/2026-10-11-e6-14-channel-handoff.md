## Current gap and proposed outcome

E6-12 persists a complete typed interview, immutable review card, named owner and explicit owner ACK. Its own drafts stop, but installed `Orchestrator._reply` and follow-up delivery do not consult this journal. A stale legacy conversation can still generate a reply. Existing interception is mutable and can expire; it is not a durable guarantee for this handoff.

Proposed bounded slice: a full administrator explicitly selects an existing canonical Dialog belonging to the service-case contact, previews its exact channel/account/recipient and confirms a permanent automation stop tied to one immutable interview handoff card. Binding and creating a pending handoff occur in one domain transaction, or an already pending/acked exact card is bound without changing its history. Owner acknowledgement remains the existing actor/card-hash operation. Old unbound interviews remain honestly labelled unbound; no contact-to-applicant identity is inferred.

## Design to audit before implementation

- An additive immutable binding table pins case/contact/dialog/interview/card hash, exact transport identity, creating operator, explicit authority/privacy policy snapshot and request key. Existing full-admin identities only; server policy defaults empty and has finite allowed channel/account scopes. Native UI never accepts a free-form recipient. Cross-case/contact/dialog/card substitution fails. Binding does not grant permission to disclose applicant facts or send a message.
- A separate server deployment allowlist of guarded channel/accounts defaults empty. It is an explicit activation boundary, not the business policy. Within an activated scope, unavailable DB/schema, malformed recipient or corrupt binding fails closed for autonomous sending. Policy expiry/removal cannot remove an existing stop. Deactivating that deployment guard is an explicit operational rollback outside this task, never an automatic fallback. Accounts outside the deployment scope preserve legacy behavior. Supported exact transport identities and any channel limits must be established from actual adapters before implementation; do not reuse phone normalization for Telegram/Bitrix identities.
- Every autonomous client send in the installed orchestrator and follow-up paths passes the guard immediately before provider invocation. Early checks may avoid unnecessary LLM work, but cannot replace the final gate. Manual manager replies and staff alerts keep their existing access checks and routing. Search all call sites and account for each autonomous path.
- No reset/unbind/resume policy is invented. A bound dialog remains stopped even after ACK, a new interview or a policy change. UI displays this consequence before confirmation. Read views show current bound status separately from the historical E6-12 card's original `not_integrated` field; old receipts are not rewritten.
- Serialize stop creation with outbound permission checks using the exact transport scope even when no binding row exists. PostgreSQL shared/exclusive transaction advisory locks are a candidate; SQLite uses an isolated writer transaction in tests. Deterministic lock order and bounded provider timeout are required. Do not pass provider callbacks through database transaction retry helpers: a lost acknowledgement must never cause a second provider invocation. Linearization concerns provider invocation, not remote delivery timing; an already invoked remote request cannot be recalled.
- No physical client delivery is performed during work. All channel callbacks and LLM/provider boundaries in tests are explicit fakes that count invocations. No production data, migration, setting or connection is changed.

## Acceptance and credible failures

Atomic exact binding/handoff and owner ACK; signed native form, strict bounded fields, current full-admin and policy checks, exact authorized retry after policy removal; wrong contact/case/account/channel/card denied. Active old LLM work must be stopped at final send; follow-up selection cannot bypass the current guard. Repeated retry/restored DB/new process still blocks. Unbound enabled scope allows normal synthetic send; unrelated account/channel remains unaffected; manual manager/staff routes remain unaffected. Bound scopes fail closed on storage/integrity failure, current policy expiry/removal and reused old interview. Concurrent send/stop orders tested on actual PostgreSQL; callback at most once even on storage teardown/commit uncertainty. Local schema/model/FK/empty downgrade, bounded recovery read/retry/new valid binding; mobile/native/no-JS/print as applicable. Full installed route tests, not only helper mocks.
