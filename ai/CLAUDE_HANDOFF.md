## 1. Сначала проверь, жив ли бот — и для КАЖДОГО канала отдельно

```bash
curl -s https://frunzetravel.kg/health
```

`ok` означает, что контейнер поднялся, и больше ничего. У нас трижды было, что
`/health` зелёный, а клиенты сидят без ответа. Настоящая проверка — две, и путать их
нельзя:

```bash
# 1. деньги на LLM
ssh frunze 'docker exec -e PYTHONPATH=/app frunze-travel-app-1 python -c "
import asyncio; from app.core import balance_guard
print(asyncio.run(balance_guard.fetch_openrouter()))"'

# 2. каналы WhatsApp — спрашиваем у Wappi, а не считаем тишину
ssh frunze 'docker exec -e PYTHONPATH=/app frunze-travel-app-1 python -c "
import asyncio; from app.core import wappi_health
print(asyncio.run(wappi_health.diagnoses_and_health()))"'
```

🔴 **Ловушка, на которой я уже обжёгся 16–19.11.** `grep 402` по логу НЕ различает,
кто ответил 402 — OpenRouter или Wappi. Я трое суток писал в отчётах «деньги на LLM
кончились», хотя OpenRouter ожил ещё 16.11 в 11:46 UTC, а 402 шли от Wappi по турам.
Увидел 402 — обязательно выясни, чей он, двумя командами выше.

Третья проверка, которая отвечает на вопрос «а доходят ли ответы до клиента»:

```bash
ssh frunze 'docker exec -e PYTHONPATH=/app frunze-travel-app-1 python -c "
import asyncio
from sqlalchemy import text
from app.admin import router as ar
async def m():
    async with ar._domain_sessionmaker()() as s:
        for r in (await s.execute(text(
            \"SELECT to_char(m.created_at,chr(39)||chr(77)||chr(77)||chr(45)||chr(68)||chr(68)||chr(39)) d, c.bot_id, m.sender, count(*) \"
            \"FROM messages m JOIN conversations c ON c.id=m.conversation_id \"
            \"WHERE m.created_at > now() - interval chr(39)||chr(55)||chr(32)||chr(100)||chr(97)||chr(121)||chr(115)||chr(39) \"
            \"GROUP BY 1,2,3 ORDER BY 1 DESC,2,3\"))).all(): print(r)
asyncio.run(m())"'
```

Если у какого-то бота пропали строки целиком — его канал мёртв, и тишина в трафике
это не «клиенты не пишут».

## 4. Что готово и ждёт ОДНОГО слова владельца

Всё это выкачено на прод и выключено тумблером. Включение — без деплоя:

```bash
ssh frunze 'docker exec frunze-travel-app-1 python -c "import asyncio; from app.core import flags; asyncio.run(flags.set_flag(\"ИМЯ\", True))"'
```

| Тумблер | Что даёт | Что произойдёт при включении |
|---|---|---|
| `panel_reports_enabled` | страница отчётов по списку Медины | ничего не ломается, просто появится раздел |
| `auto_stage_on_manager_reply_enabled` | «Новый лид» → «В работе» по сообщению менеджера | вперёд работает сразу; старые 1279 карточек не двинутся, для них отдельная команда |
| `manager_sees_direction_cases_enabled`<br>`manager_can_take_colleague_dialog_enabled`<br>`reassign_moves_tasks_enabled` | три прямых ответа Гриши от 05.11 | менеджер начнёт видеть всех в своём направлении и сможет забрать клиента коллеги |
| ~~`cases_write_enabled`~~ | тумблера НЕТ | дела пишет `service_cases_enabled`, ON с 19.10; дел 0, потому что их не заводят |
| `auto_close_after_touches_enabled` | автозакрытие после трёх касаний | калибровка сделана; при пороге 7 дней ложных 8.1% по визам |

Разовые команды, которые ждут решения (все умеют показ без записи):

Скрипты лежат в `scripts/` и в образ НЕ копируются — их кладут в контейнер перед
запуском. Полный цикл (на примере переноса карточек):

```bash
scp scripts/backfill_lead_stage.py frunze:/root/
ssh frunze 'docker cp /root/backfill_lead_stage.py frunze-travel-app-1:/tmp/bls.py'
ssh frunze 'docker exec -e PYTHONPATH=/app frunze-travel-app-1 python /tmp/bls.py'           # показ
ssh frunze 'docker exec -e PYTHONPATH=/app frunze-travel-app-1 python /tmp/bls.py --apply'   # запись
```

`PYTHONPATH=/app` обязателен: скрипт лежит в `/tmp`, без него пакет `app` не найдётся.
После `--apply` сразу забрать бэкап из контейнера — `docker cp`, иначе ближайший
деплой пересоздаст файловую систему вместе с ним.

Что есть: `backfill_lead_stage.py` (перенос стадий), `owner_mirror_check.py` (18
спорных расхождений владельца, только чтение), `heal_owner_mirror.py` (их лечение),
`auto_close_replay.py` (калибровка порога). У всех показ по умолчанию, запись — по
явному `--apply`.

## 6. Чего НЕ делать

- **Не переключать домен `crm.frunzetravel.kg`** на отдельный стек CRM: сейчас он ведёт
  на панель, которой пользуются Медина с Элизой. Переключение отберёт у них рабочий
  инструмент и даст пустую систему.
- **Не включать автозакрытие** без решения по порогу: оно ставит клиенту «не выходит на
  связь».
- **Не менять цены клиенту** без слова владельца.
- **Не писать в прод-данные** без показа и бэкапа. Образец — `heal_owner_mirror.py`.
