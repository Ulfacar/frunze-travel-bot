## 2. Как работать с Аланом (протокол, важнее всего остального)

**Доказательство важнее уверенности.** Предыдущий агент мог ошибиться, прошлый отчёт мог
устареть, исполнитель не судья собственной работы. Наш повторяющийся провал — не баги, а
отчёты, которые врут.

1. **Диагностику даю сразу**, не спрашивая разрешения посмотреть.
2. **Чиню целиком**, а не по кусочку — но **на прод выкатываю только по прямому слову Алана**.
   Само по себе «почини» деплой не разрешает.
3. **Всё, что меняет поведение для клиента, включается флагом, и флаг по умолчанию OFF.**
   Выкатили код — поведение не изменилось; включаем отдельным решением.
4. **Называю класс риска до начала работы** и веду задачу по нему:
   **S** — текст, лог, тест, док: сделал → `pytest -q` → показал дифф.
   **M** — несколько файлов, клиента не касается: гейт до кода → `pytest -q` +
   `prod_traps_check --diff-base HEAD` → ревью по диффу.
   **B** — поведение бота (промпт, воронка, ответ клиенту): M + флаг OFF + замер на реальных данных.
   **C** — миграции, деньги, рассылки, ключи, прод-данные, детекторы с порогами: B +
   два независимых ревью, одно из них **кросс-вендорное** (`codex review` / `codex exec`) +
   калибровка на истории (`alert_replay.py`) + решение Алана.
   Сомневаюсь между классами — беру старший.
5. **Границы дифа объявляю до работы**, после — сверяю `git diff --stat`. Каждый лишний файл
   объясняю. Расширять задачу, «раз уж я здесь», нельзя: замеченное предлагаю, а не делаю молча.
6. **`/health` — не доказательство.** Различаю: `PROD_HEALTHY` (контейнер поднялся) и
   `PROD_FUNCTIONALLY_VERIFIED` (функция вызвана на проде и вернула то, что должна). После
   деплоя обязан сделать второе — вызвать изменённое в боевом контейнере и показать вывод.
   `smoke_test.py` по проду не гонять: он создаёт мусорный диалог через вебхук.
7. **Отчёт заканчиваю доказательствами:** что сделано / где (файлы, коммит) / чем проверено
   (команда и число) / где проверено (локально, образ, прод) / **что осталось непроверенным**.
   «Работает», «тесты зелёные», «деплой прошёл» — не доказательства. Не мерил — так и говорю.
8. **Сверяю диф, а не отчёт агента.** Был случай: отчёт заявил предохранители, которых в
   коде не было. Перед любым прод-действием читать диф/хеш.
9. **Статусы требований:** `DONE / PARTIAL / BROKEN / MISSING / BLOCKED / UNKNOWN`. Работающее
   не переписываю без доказательства регрессии; `UNKNOWN` превращаю в факт проверкой, не догадкой.
10. **Стоп-слова.** `NEEDS_HUMAN_DECISION` — бизнес-политика не определена, деньги, необратимое,
    архитектурный выбор меняет продукт. `BLOCKED` — доказательство получить нельзя, состояние
    прода противоречиво. Молча выбирать продуктовое решение за Алана запрещено.
11. **Не добавляю лишнего.** Не требуется задачей, не нужно для корректности, не нужно сейчас —
    не делаю, записываю как долг.
12. Язык — русский, неформальный. Готовые тексты и решения ценятся выше вариантов на выбор.
13. На пересланные скриншоты переписки — сначала **разбор ситуации**, готовый текст ответа
    одной строкой в конце, а не вместо разбора.
14. **Протокол подтверждаю делом, а не словом** (просьба Алана 01.10.2026). В каждом ответе
    виден след: класс риска, пройденный шаг, команда и число. «Работаю по протоколу» без
    отпечатка — такое же пустое заявление, как «тесты зелёные». Нечего показать на шаге —
    пишу, что доказательства нет.

## 2a. Команда моделей (схема 28.10.2026, прямое распоряжение Алана)

Работаем одной командой из терминала Алана. **Ведущий — Opus**, остальных вызывает сам.

| Кто | Вендор | Берёт |
|---|---|---|
| **Opus** | Anthropic | класс риска, ТЗ, гейт, свой код, ревью кода Codex, прод-действия по слову Алана |
| **Codex** (`gpt-6-astra`) | **OpenAI** | DevOps, CI, свой код по ТЗ, ревью кода Claude, эталоны тестов по тексту ТЗ/PDF |
| **Sonnet** | Anthropic | объём: инвентаризация, перебор, массовые правки по готовой схеме |
| **Fable** | Anthropic | архитектура, инварианты, аудит класса CRITICAL |

Запуск Codex: `codex exec -m gpt-6-astra --sandbox read-only|workspace-write -C "<каталог>" -`,
промпт через stdin. Проверено 28.10: `codex-cli 0.163.0`, режима «Codex как MCP-сервер» нет.

**Автор и проверяющий — всегда разных вендоров.** Код Claude проверяет Codex; код Codex
проверяет Opus или Fable. Codex не ревьюит себя, Claude не ревьюит себя. Если Codex не
отвечает — проверяет другая модель Claude с пометкой **«без кросс-вендора»**, и работа при
этом не стоит.

**Прод, деплой и флаги — только по слову Алана. Codex на прод не ходит** ни при каких
условиях: он готовит, выполняет Opus после «да». Субагентам Claude прод-запись не поручается.

- Docker — snap-версия: работает только из `/root` и не читает скрытые файлы,
  поэтому `.env` называется **`prod.env`** и он **вне git** (в нём боевые токены).

**Деплой — только через скрипт, руками compose не поднимать:**

```bash
# локально: отдать код на сервер (прод тянет НЕ с GitHub, а со своего bare-репо)
git push prod <branch>
# на сервере:
/root/frunze-travel/scripts/deploy_prod.sh <branch>     # дефолт: fix/tours-search-quality
/root/frunze-travel/scripts/rollback_prod.sh [commit]   # откат, если поломка логическая
```

`deploy_prod.sh` сам бэкапит prod.env, ждёт `/health` и **откатывается**, если приложение
не поднялось. Три ловушки, зашитые в скрипт и стоившие нам инцидентов:
1. `docker compose` без `--env-file prod.env` → `MANAGERS` пустой, логины менеджеров в
   панель отваливаются **молча**, при этом `/health` зелёный.
2. Без `-f docker-compose.vps.yml` контейнер лезет на 80/443, где уже сидит системный nginx.
3. `-f docker-compose.vps.yml` **без базового** `-f docker-compose.yml` → «service "app" has
   neither an image nor a build context». Рабочая форма (22.09 наступили на это, поднимая
   контейнер руками после подмены ключа):
   `docker compose -f docker-compose.yml -f docker-compose.vps.yml --env-file prod.env up -d app`

**Гит-ремоуты:** `origin` = GitHub (`Ulfacar/frunze-travel-bot`), `prod` =
`ssh://root@62.171.185.155/root/frunze-repo.git`. Рабочая ветка — **`feat/owner-answers-2026-11-05`**
(с 05.11.2026; прежняя `fix/tours-search-quality` осталась в истории). `main` отстаёт на

## 5. Внешние системы и их подводные камни

**TourVisor** (подбор туров, XML API, аккаунт `frunzetravel@mail.ru`)
- Из Бишкека реально вылетают **Турция, ОАЭ, Мальдивы, Азербайджан**. По Египту, Таиланду,
  Кипру поиск честно возвращает **0 отелей** — и бот раньше врал, что дело в бюджете.
- Обязательны `childage1..N` — без возрастов детей выдача пустая.
- Валюта в ответах плавает (EUR), звёздность отелю LLM недоступна — берём из полей.
- Есть квота (`quota.py`); тариф меняли, «Горящие туры» — отдельный платный пакет.

**Wappi** (мост WhatsApp) — каналы регулярно отваливаются по QR и это **не видно по трафику**:
тишина не отличает мёртвый канал от тихого. Поэтому сторож v3 спрашивает у Wappi
**статус профиля**, а не считает молчание. Подписки платные, у GetVisa истекала 20.08.2026 —
проверить оплату.

**Bitrix24** (`getvisakg.bitrix24.kz`, inbound REST-вебхук; токен НЕ хранить в репо/памяти)
- **Два потока лидов, это корень жалобы «мы не видим бота»:** поток Wappi → Открытые линии
  (там сидят менеджеры) и поток нашего бота (лиды падали на служебный аккаунт 155383).
- Реплики бота попадают в чат Открытой линии только с параметром **`bot_id=external_api`**.
  Ответы менеджеров возвращаются через `outgoing_message_api`.
- ID менеджеров: Медина 96451, Элиза 110841, Адеми 155313, Айсина 155267.
- Разница поведения виз и туров = **тип очереди Открытой линии** (`evenly` против `all`).
- Портал молча съедает эмодзи и BBCode в карточках — это дефект портала, не наш.
- 🔴 **Продажи в CRM не заносятся с 13.06** → конверсия объективно не меряется. Любые
  выводы про «сколько продали» через Bitrix недостоверны: у таргетологов 158 продаж
  против 7 сделок в CRM.

**LLM** — OpenRouter, роутинг Haiku/Sonnet + кэш. Расход **~$2/сутки** на ноябрьском
трафике, то есть порядка $60/мес (прежняя оценка «$17/мес» верна для сентября и устарела
втрое). 98.6% токенов — ВХОДНЫЕ: платим за промпт, не за ответы. Туры съедают 78% счёта
при 18 000 входных токенов на вызов против 1100 у виз; Sonnet берёт 36% счёта за 4.5%
вызовов, потому что в турах он включается по словам «цена/стоимость/бронь». Кэш работает,
но стоит только на системном блоке — растущая история оплачивается каждый ход заново.

**STT (голосовые)** — OpenAI. Технически 100% успех, ~28 голосовых/день. Но **кыргызского
языка в модели нет**: 54% кыргызской речи — нечитаемая каша. Отсюда `stt_guard` — фильтр
доверия к расшифровке.

## 7. Бизнес-правила, которых нет в коде очевидно

- **Часы приёма:** разговаривать бот может в любой день, а **визит в офис назначать только
  пн–сб**. Это перекрывает «работаем ежедневно» из туровой анкеты — бот однажды записал
  клиента на воскресенье.
- **Визы:** бот называет официальный прайс (250$/100€ и т.д.). Депозиты, проценты и любые
  гарантии выдачи — **запрещены**. По «нашим» странам консультирует сам, по чужим
  (Бразилия и пр.) сразу отдаёт менеджеру.
- **Цены по турам** публикует только админ; клиенту — вилка как приманка в офис.
- **Ручное важнее бота:** менеджер перехватил диалог → бот замолкает (`intercept.py`, TTL).
- **Владение диалогом закреплённое.** С 05.11.2026 решением заказчика (ответы 2.1 и 2.2)
  перехват внутри СВОЕГО направления разрешён: менеджер видит всех клиентов своего
  направления и может забрать клиента коллеги себе — вместе с перепиской и услугой.
  Между направлениями запрет остался; передать клиента ТРЕТЬЕМУ менеджеру по-прежнему
  может только админ. Два флага, оба OFF: `manager_sees_direction_cases_enabled`,
  `manager_can_take_colleague_dialog_enabled`. Правила — `app/domain/permissions.py`
  (переписка) и `app/domain/service_authz.py` (услуги), они обязаны совпадать.
  **Это решение владельца, а не упущение: не возвращать прежнее правило без него.**
- **Бот — ночной диспетчер, а не продавец.** Это рефрейм всей ценности: медиана ответа
  живого менеджера была 3 часа, 20% лидов приходят ночью.
- Бот знает сегодняшнюю дату — её инъектим в промпт каждый ход (без этого он гадал месяц).
